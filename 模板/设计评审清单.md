## Agent 设计评审清单

评审一个 agent 项目时使用。每个问题都要求对方拿出证据：文件、追踪记录、测试。清单随课程各阶段逐步补全，下面是起始版本，请按自己的经验增删。对应 Day97。

### 一、该不该用 agent

- 这个任务用一次模型调用或固定工作流能否完成？为什么不行？
- 每一步的结果能否被验证？靠什么验证？
- 出错的代价是什么，能否撤销？

### 二、评估

- 一次提示词或模型改动上线前，怎样知道它没有让别的问题变差？
- 评估集在哪，多少条，谁标注的，上次更新是什么时候？
- 评估集里有没有“应当弃答”和“不应出现”的用例？
- 模型评审员是否对照人工标注校准过？
- 检索类系统：检索和生成是否分开评估？
- 编码类 agent：验收标准是测试通过、构建通过，还是人工评审通过？

### 三、编排

- 每个任务为什么是工作流或 agent？
- 循环有没有步数、token、时间上限？达到上限时用户看到什么？
- 有副作用的步骤在恢复时会不会重复执行？
- 人工确认设在哪，审批人能看到依据吗？

### 四、工具与安全

- 这个 agent 占了致命三要素里的几项？去掉了哪一项？
- 外部内容（工单、网页、导入的 Skill、MCP 工具描述）能否影响系统提示词或触发写操作？
- 工具有没有注册表和风险分级？
- 最终放行靠的是模型判断，还是确定性规则？

### 五、权限与平台底座

- 检索是否按提问人的权限过滤？在哪一层过滤？
- 向量、摘要、图谱、缓存、追踪日志是否继承了原始内容的权限？
- 无人值守的 agent 以谁的身份运行？
- 模型调用是否只有一条路径？能否查到一次回答实际用的模型？
- 追踪用的是开放标准吗？有没有保留期？

### 六、多 agent 与长时运行

- 为什么需要多个 agent？是为了上下文、权限、工具数量，还是并行？
- agent 之间交接的内容是否类型化、可记录、可回放？
- 长任务的进度记录在哪，新一轮怎样接上？
- 主动发起的 agent：采纳率是多少，怎样防止打扰用户？

### 七、运行与治理

- 成本怎样核算到任务和用户？有没有预算上限？
- 出了问题，从用户反馈到定位原因需要几步？
- 写操作的审计记录能否对应到一个具体的人？
- 模型或提示词升级的发布和回滚流程是什么？

### 评审结束时

写一页纸交给项目组：三到五条按优先级排序的发现，每条包含问题、可能的后果、建议的下一步。
