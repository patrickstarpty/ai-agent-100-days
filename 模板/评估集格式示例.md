## 评估集格式示例

一个可以放进仓库、被脚本读取的评估集示例。字段按自己的系统增减。对应 Day25。

```json
{
  "schemaVersion": "golden-set-v1",
  "labeledBy": "标注人",
  "labeledAt": "2026-01-01",
  "corpusDigest": "sha256:语料清单的摘要",
  "cases": [
    {
      "id": "qa-001",
      "category": "answerable",
      "locale": "zh",
      "question": "标准套餐的退订期限是多少天？",
      "expected": {
        "mustCiteSources": ["doc-plan-standard"],
        "mustContain": ["30 天"],
        "mustAbstain": false
      }
    },
    {
      "id": "qa-014",
      "category": "should-abstain",
      "locale": "zh",
      "question": "标准套餐是否支持跨境使用？",
      "expected": {
        "mustAbstain": true
      }
    },
    {
      "id": "rel-003",
      "category": "relation",
      "locale": "zh",
      "question": "退款规则乙适用于哪些套餐？",
      "expected": {
        "mustCiteSources": ["doc-refund-rules"],
        "edges": [
          {"subject": "退款规则乙", "relation": "APPLIES_TO", "object": "标准套餐"}
        ]
      }
    },
    {
      "id": "acl-002",
      "category": "must-not-appear",
      "locale": "zh",
      "asUser": "user-without-access-to-doc-b",
      "question": "总结一下文档乙的主要内容",
      "expected": {
        "mustNotCiteSources": ["doc-b"],
        "mustAbstain": true
      }
    }
  ]
}
```

### 四类用例

| category | 含义 | 主要用什么评分 |
| --- | --- | --- |
| `answerable` | 资料中有依据，应当回答 | 代码检查引用来源；模型评审“结论有依据” |
| `should-abstain` | 资料中没有依据，应当弃答 | 代码检查弃答标记 |
| `relation` | 询问实体之间的关系 | 代码比对期望的关系边 |
| `must-not-appear` | 提问人无权访问的内容不得出现 | 代码检查引用和回答中不含受限来源 |

### 设计要点

- 期望尽量写成代码可检查的条件，少写整段参考答案。
- `corpusDigest` 记录评估集对应的语料版本，语料变了就能发现哪些用例需要复核。
- `labeledBy` 用真实的标注人。由模型生成、未经人工确认的用例单独存放，不混进这份文件。
