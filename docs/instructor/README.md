## 讲师材料说明

> 讲师用，不进学员目录。

**一句话**：这个目录是讲师的备课包——判分标准、验收方法和排期表，不是课程正文的一部分，不发给学员。

**这些文件不发给学员**

`docs/instructor/` 下的每一份文件开头都写着“讲师用，不进学员目录”。仓库本身是公开的，任何人都能在这里看到这些文件，但它们的用途是帮讲师判分、验收和排课，不是给学员预习或对照抄的答案。把它们转发给学员、挂进课程仓库的目录结构，或者在课堂上提前展示评审演练的参考答案，都会让对应的练习失去意义——学员会直接套用答案，而不是自己走一遍错误分析、评审或排期的过程。带班时请只在批改、验收或讲评环节内部使用这些文件。

### 每个文件是什么

- **`自检参考答案-DayNN-MM.md`**（十份，每个阶段目录一份，命名与 `DayNN-MM` 目录一致）：对应阶段每一课两道自检题的参考要点，每题 2～4 行。用来在批改学员的自检作业、或课堂随堂提问时核对要点是否齐全，不是要学员背诵的标准答案——自检题本身没有唯一的标准表述。
- **`评审演练答案-Day98.md`、`评审演练答案-Day99.md`**：Day98、Day99 两节评审演练课里虚构设计摘要的全部埋点、每条发现的问题/后果/下一步、排序理由和讲评时常见的问题。用来批改学员提交的评审报告。
- **`复盘评分标准.md`**：Day34、46、66、76、94、97 六节复盘课产出的评分标准，按“缺项 / 合格 / 优秀”三档给出可检验的表述。
- **`实战课验收方法.md`**：Day10、22、56、86 四节阶段实战课的验收方法，给每条验收项配上具体的检验手段（测试代码、grep 命令、现场提问的问法），以及替身模型的通用写法。
- **`压缩排期.md`**：企业培训场景下的课时压缩表，20 次课和 10 次课两个版本，说明哪些课合讲、哪些课自学、实战课和复盘课怎样安排。
- **`讲师提示.md`**：按十个阶段分节，每节列这一阶段最容易讲错或学员最容易卡住的地方，以及对应的演示建议。

### 怎样用它们组织一次培训

**开课前**

- 这门课本身没有要求特定的运行环境，只需要一个能跑 Python 3.11+ 的环境、一个可用的模型 API（litellm 支持的任意供应商都可以），以及 `samples/` 目录（知识检索和多 Agent 两个阶段的练习要用到虚构语料和样例轨迹）。开课前把这三样准备好，比在课堂上现场装环境节省大量时间。
- 让学员提前读完 Day02（调用模型 API）里 `litellm` 的接入说明，自己配好模型名和环境变量里的 key，带着一个能跑通 `chat()` 的 `llm.py` 来上第一次课。没有装好环境的学员，课堂演示和讨论都插不上手，容易拖慢整组进度。
- 讲师自己通读一遍 `docs/HANDOFF.md` 和 `docs/WRITING_BRIEF.md`，熟悉课程的硬性要求、课与课之间的引用关系（哪些概念在哪一课第一次出现、后面哪几课会用到），这样回答学员的提问时才能准确指到具体的 `DayNN`，而不是含糊地说“后面会讲”。

**每课节奏**

- 按 `压缩排期.md` 给出的课时表安排：一次课通常合讲好几个普通课时，先用“一句话→放在全局看→打个比方→核心概念”的顺序带着讲一遍每课的核心，再留时间讨论和答疑；动手练习里的“20 分钟必做”可以当堂做，“课后选做”和自检题留给学员课后完成。
- 不要在课堂上逐字复述课文。课文已经写得足够简单直白，课堂时间更适合用来过一遍示例代码背后的权衡、回答学员提问、现场跑一次脚本或演示一次失败案例——`讲师提示.md` 里按阶段列的易错点，大多就是值得当堂演示的地方。
- 自检题不批改，但讲师可以抽查几道，对照对应阶段的 `自检参考答案-*.md` 看学员的回答是不是抓住了要点，而不是看措辞是否一致。

**实战课怎样验收**

- 按 `实战课验收方法.md` 的通用做法：学员或小组现场演示 10～15 分钟，先跑一遍自动化测试，再由讲师从“验收清单：必做”里抽 3～5 条现场演示，其中至少一条是边界与安全类（例如 Day10 的路径逃逸、Day56 的白名单外工具拒绝）。“验收清单：进阶”由学员自选一两条展示，不计入是否通过。
- 四个实战课（Day10、22、56、86）的验收项和检验方法已经按课文当前版本逐一配好，照着对应小节走就行；课文调整时按条目内容对应，不要求逐字匹配。

**复盘怎样评分**

- 按 `复盘评分标准.md` 的“缺项 / 合格 / 优秀”三档：合格档的每一条都要满足才算合格，优秀档在合格的基础上再满足若干条（具体条数见各课说明）。课文自带的“阶段验收”清单是硬性底线——没过阶段验收的，产出写得再完整也只能评缺项。
- 评分时可以请学员当场口头回答一两个追问，讲不清楚的部分按缺项处理；每条结论都要求学员附上证据位置（文件路径、测试名、追踪链接），只写“有”“已考虑”视为没写。
