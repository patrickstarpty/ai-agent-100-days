```python
# main.py
from agent import run_turn

SYSTEM = "..."   # 自己写

def main() -> None:
    messages = [{"role": "system", "content": SYSTEM}]
    while True:
        try:
            user_input = input("> ").strip()
        except (EOFError, KeyboardInterrupt):
            break
        if user_input in {"exit", "quit"}:
            break
        if not user_input:
            continue
        messages.append({"role": "user", "content": user_input})
        result = run_turn(messages)          # 待补：run_turn 抛出异常时如何收尾
        print(result.text if result.completed else f"[未完成] {result.text}")
        print(f"[步数 {result.steps} | 输入 {result.prompt_tokens} | 输出 {result.completion_tokens}]")

if __name__ == "__main__":
    main()
```

**三个容易做错的地方**

读文件工具的目录限制。模型给出的 `path` 可能是 `../llm.py`、绝对路径，或者指向目录外的符号链接。检查字符串里有没有 `..` 是不够的。可靠的做法是先把路径拼到 `ROOT` 下并用 `Path.resolve()` 解析成真实路径，再用 `is_relative_to(ROOT)` 判断结果是否仍在目录内，不在就拒绝。这个限制必须写在工具代码里。只在提示词里写“不要读取其他目录”不构成限制。

“轮”和“步”的区别。一轮是用户的一次输入到助手的一次回答；一轮之内，agent 循环可能走多步。`messages` 跨轮保留，步数上限按轮计算，用量按轮统计。

一轮出错之后的历史。如果 `chat` 在某一轮抛出异常，`messages` 的末尾可能停在 user 消息，或停在一组工具结果上。要决定如何收尾，例如把这一轮追加的消息全部撤掉，再提示用户重试。无论怎么选，都要保证下一轮发送的消息序列是合法的，并且程序回到提示符，不退出。

### 动手练习

按上面的结构实现助手。先在 `cases.md` 里写下每条验收项对应的具体问题和期望行为，再写代码，最后逐条验证。

**验收清单**

基本功能

- [ ] 问“(17.5 + 4) * 3 等于多少”，进度输出显示调用了 `calculate`，答案是 64.5。
- [ ] `workspace/` 里放一个 `notes.txt`，针对其内容提问，助手调用 `read_file` 并答对。
- [ ] 问一个需要两个工具配合的问题（例如文件里有几个数字，要求求和），两个工具都被调用，结果正确。
- [ ] 问一个不需要工具的问题，助手直接回答，没有多余的工具调用。
- [ ] 第二轮追问“刚才那个结果再乘以 2”，助手能用到上一轮的结果。

边界与安全

- [ ] 要求读取 `../llm.py`：工具返回错误，助手如实说明无法读取，程序不崩溃。
- [ ] 要求读取一个绝对路径（如 `/etc/hosts`）：同上。
- [ ] 要求读取不存在的文件：工具返回错误，助手说明文件不存在，没有编造内容。
- [ ] 读取一个超过长度上限的文件：进入上下文的内容被截断并带有标记，助手在回答里说明只读到了一部分。
- [ ] 让它计算 `1 / 0`：错误作为工具结果返回，助手说明无法计算。
- [ ] 代码里没有 `eval` 和 `exec`。

循环与预算

- [ ] 把 `max_steps` 设为 1，问需要工具的问题：输出明确标注未完成，没有给出一个看似正常的答案。
- [ ] 每一轮结束都打印步数、输入 token 和输出 token，数字是这一轮所有模型调用的合计。
- [ ] 每次模型调用都设置了 `max_tokens`；`finish_reason` 为 `length` 时按未完成处理。

错误处理

- [ ] 临时让 `completion` 的前两次调用抛出可重试的异常：助手自动重试并正常回答，日志里有每次重试的记录。
- [ ] 临时让 `completion` 一直失败：重试用尽后显示清楚的错误信息，程序回到提示符，下一轮可以正常使用。
- [ ] 整个项目只有 `llm.py` 一处导入 `litellm`。
- [ ] 每次模型调用都有一行日志，包含模型名、耗时、token 数和 `finish_reason`。

**进阶**

- 最终回答改为流式输出（Day08），同时保持用量统计正确。
- 增加 `/usage` 命令，显示整个会话的累计用量和估算费用。
- 增加一个有副作用的工具 `write_file`（同样限制在 `workspace/` 内），执行前在命令行向用户展示将要写入的路径和内容，得到确认后才执行。
- 给会话设一个总 token 预算，接近上限时提示用户，超过后拒绝继续并说明原因。
- 把 `cases.md` 里的用例写成脚本自动运行，输出通过数。这是 Day23–34 评估阶段的起点。
