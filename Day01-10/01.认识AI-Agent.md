## Day01 - 认识 AI Agent

> 大模型应用基础 ｜ 建议用时 1 小时

> **一句话**：Agent 就是“模型 + 工具 + 循环”：模型自己决定下一步做什么，直到它认为任务完成。
>
> **放在全局看**：这是整门课的地图。Day02~09 把这个循环拆成零件逐个讲，Day10 装成第一个能用的助手；之后九个阶段（Day11~100）都在回答同一个问题：怎样让这个循环可靠、可控、可评估。

### 学习目标

- 能用一句话说清 agent 是什么，并区分单次模型调用、固定工作流和 agent。
- 能说出 agent 系统的五个组成部分，以及每个部分出问题时的表现。
- 知道 100 天的十个阶段各自解决什么问题。

### 核心概念

**打个比方**：单次调用像问路，对方答一句就结束；工作流像照着菜谱做菜，步骤是写死的；agent 像把任务交给一位同事，怎么做由他边做边定。

**Agent 的定义**

Agent 是在循环里工作的模型：它看当前情况，自己决定下一步做什么，调用工具，读工具返回的结果，再决定下一步，直到它判断任务完成。骨架只有几行（伪代码，Day06 会写出可运行的版本）：

```python
while True:
    reply = call_model(messages, tools)
    if not reply.tool_calls:      # 模型不再要求调用工具，任务结束
        break
    for call in reply.tool_calls:
        messages.append(run_tool(call))
```

这段代码里没有任何业务步骤。先查什么、后算什么、何时停下，都由模型在运行时决定。

**三种形态**

| 形态 | 步骤由谁决定 | 适合 | 代价 |
| --- | --- | --- | --- |
| 单次模型调用 | 没有步骤，一问一答 | 分类、抽取、改写、总结 | 最便宜，最容易测试 |
| 固定工作流 | 你写的代码 | 步骤能事先列清楚的流程 | 多次调用，路径可预测 |
| Agent | 模型 | 步骤无法事先列全的开放任务 | 调用次数不固定，成本、延迟和结果的波动都更大 |

选择的原则是用能可靠完成任务的最简单形态。Day35 会专门讨论工作流和 agent 的取舍，这个阶段先把两者共用的基础打牢。

**Agent 擅长和不擅长的事**

适合交给 agent 的任务通常有三个特点：步骤数和顺序取决于中途看到的内容；每一步的结果能从环境里得到反馈（测试通过或失败、查询有结果或没结果）；中途出错可以重来，代价可以接受。排查故障、在代码库里完成一个改动、跨多个数据源找答案，都属于这一类。

以下情况 agent 的表现不好，或者不值得用：

- 步骤固定的流程。用工作流更便宜，也更容易保证每次都一样。
- 对延迟敏感的交互。每多一步就多一次模型调用。
- 错误代价高且不可撤销的操作，例如付款、删除数据。这类步骤需要人工确认，不能让循环自己走完。
- 结果难以验证的任务。Agent 每一步都可能出错，错误会沿着后续步骤累积，没有验证手段就发现不了。

**Agent 系统的五个部分**

| 部分 | 作用 | 出问题时的表现 |
| --- | --- | --- |
| 模型 | 理解任务，决定下一步 | 推理错误，选错工具 |
| 工具 | 让模型能读取数据和执行操作 | 该调用时不调用，参数填错 |
| 上下文 | 模型每一步能看到的全部信息 | 忘记前面的结论，被无关内容干扰 |
| 编排 | 控制循环：何时继续、何时停、何时等人确认 | 死循环，越权操作，中断后无法恢复 |
| 评估 | 判断系统做得对不对 | 改动之后不知道是变好还是变坏 |

初学者的注意力通常集中在模型上。实际项目里，大部分工程量花在后四项。

### 动手练习

**20 分钟必做**

1. 准备环境：安装 Python 3.11 或更高版本，新建虚拟环境，执行 `pip install litellm pydantic`。准备好一个模型供应商的 API key，按该供应商的要求设置成环境变量，不要写进代码。
2. 从自己的工作里选三个想用大模型解决的任务，分别归入“单次调用 / 固定工作流 / agent”，各写一句理由。归为 agent 的任务，再写出它每一步能从哪里得到反馈。

**课后选做**

3. 对照五个部分的表格，写下你用过的某个 AI 产品的一次失败经历，判断问题最可能出在哪一部分。
