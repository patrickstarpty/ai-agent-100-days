## Day27 - LLM 评审员与校准

> 评估 ｜ 建议用时 1 小时

> **一句话**：可以让模型来当评审，但要先证明它和人的判断一致。
>
> **放在全局看**：模型评审员接手 Day26 代码判不了的那部分，例如结论能否从引用推出，它自己的可信度靠 Day24 那样的人工标注来担保。校准过的评审员在 Day31 对线上样本运行，在 Day33 成为平台上的 LLM-as-a-Judge；Day32 换模型时它要重新校准。

### 学习目标

- 能为一种失败类型写出评审标准（rubric），并写出调用评审员的代码。
- 会用一致率和两类错误率验证一个模型评分器是否可信。

### 核心概念

**打个比方**：像培训一位新阅卷老师：先让他和资深老师各自判同一批卷子，分歧小了才让他独立阅卷。

**一个评审员只判一种失败**

“请给这个回答的整体质量打分”得到的结果既不稳定也无法行动。把评审员拆开，每个只回答一个是非题，例如“回答中的每个结论是否都能从被引用的片段推出”。

**评审标准的写法**

- 给出明确的通过条件和不通过条件。
- 各给两三个带解释的例子，尤其是边界情况。
- 要求先写理由再给结论，方便事后检查它为什么这么判。

**校准：把评审员当作一个分类器来验证**

1. 人工标注一批样本（通过/不通过）。
2. 拆成三份：一份用来写和调评审标准，一份用来反复验证，一份留到最后只用一次。
3. 除了一致率，再分别看两类错误率：漏判率（人判不通过、它判通过）和误判率（人判通过、它判不通过）。只看一致率会被样本不平衡掩盖问题。
4. 评审标准或评审模型换了，重新校准。

**评审员与两项指标的代码**

评审员沿用 Day02 的 `chat` 和 Day04 的 JSON 模式，只判“结论是否都能从引用片段推出”这一件事：

```python
import json
from llm import chat

RUBRIC = """你是评审员，只判断一件事：每条结论是否都能从它所附的片段推出。
通过：每条结论里的数字、日期、对象和适用条件，都能在所附片段里找到。
不通过：任何一条结论出现片段里没有的事实，或者把片段里的条件说错。
先写理由，再给结论。只输出 JSON：{"reason": "...", "verdict": "pass" 或 "fail"}"""

def judge(claims: list[dict]) -> str:
    """claims: [{"text": 结论, "evidence": [片段原文, ...]}]，返回 "pass" 或 "fail"。"""
    resp = chat([{"role": "system", "content": RUBRIC},
                 {"role": "user", "content": json.dumps(claims, ensure_ascii=False)}],
                response_format={"type": "json_object"})
    verdict = json.loads(resp.choices[0].message.content).get("verdict")
    return verdict if verdict in ("pass", "fail") else "fail"   # 格式不对按不通过处理，并记日志
```

校准时把同一批样本的人工结论和评审员结论配成对，算三个数：

```python
def rate(part: int, whole: int) -> float | None:
    return part / whole if whole else None      # 分母为 0 时不给数，避免误导

def calibrate(pairs: list[tuple[str, str]]) -> dict:
    """pairs: [(人工结论, 评审员结论)]，取值都是 "pass" 或 "fail"。"""
    human_fail = [j for h, j in pairs if h == "fail"]
    human_pass = [j for h, j in pairs if h == "pass"]
    return {
        "agreement": rate(sum(h == j for h, j in pairs), len(pairs)),
        "missed_fail_rate": rate(human_fail.count("pass"), len(human_fail)),   # 漏判
        "false_fail_rate": rate(human_pass.count("fail"), len(human_pass)),    # 误判
    }

pairs = [("pass", "pass")] * 90 + [("fail", "pass")] * 10   # 一个什么都放行的评审员
print(calibrate(pairs))
# {'agreement': 0.9, 'missed_fail_rate': 1.0, 'false_fail_rate': 0.0}
```

这个例子里一致率有 0.9，可它一个失败都没抓住。漏判率对应“没抓住的真失败”，误判率对应“冤枉的好回答”，两者都要看，并且要有足够多的人工不通过样本，漏判率才有意义。

**警惕过高的分数**

评审员给出的通过率长期接近 100%，更可能说明评估集太容易或评审员太宽松。

### 动手练习

**20 分钟必做**

1. 为“回答有依据”这一项写评审标准，包括通过条件、不通过条件、三个例子，替换上面的 `RUBRIC`。
2. 从 Day26 的运行结果里取 20 条回答，自己先逐条标通过或不通过，再用 `judge` 判一遍，用 `calibrate` 算出一致率、漏判率和误判率。

**课后选做**

- 写下校准计划：谁来标注、标多少条、怎样拆成三份、多久重做一次。
- 把漏判的几条拿出来看，判断是评审标准没写清，还是例子不够，改一版再算一次，只在开发用的那一份上调。
