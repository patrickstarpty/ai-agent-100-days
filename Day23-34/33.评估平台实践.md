## Day33 - 评估平台实践

> 评估 ｜ 建议用时 1 小时

> **一句话**：评估集的权威版本留在仓库里，评估平台负责跑实验、存追踪和分数、组织人工标注。
>
> **放在全局看**：前面几课的评估集、评分器和实验方法都是纯 Python，这一课把它们接到一个平台上，以 Langfuse 为例。追踪的接入见 Day69，CI 里怎样调用见 Day30；换成别的平台，对应关系基本不变。

### 学习目标

- 能把数据集、实验、评分、标注这几个概念对应到 Langfuse 的对象上。
- 能说清仓库和平台各自负责什么。
- 能把 Day26 的评分器接到一次 Langfuse 实验里。

### 核心概念

**打个比方**：像学校的题库和阅卷系统：题库的正本由教研组锁在档案柜里，改题要走审批；阅卷系统负责发卷、收卷、判分、存成绩，老师也在上面复核有争议的卷子。阅卷系统里看到的好题，要交回教研组审定后才进题库。

**概念对应**

| 本阶段的概念 | Langfuse 里对应的对象 |
| --- | --- |
| 评估集（Day25） | Dataset：一组 dataset item，名字在项目内唯一 |
| 一条用例 | Dataset item：`input`，可选的 `expected_output` 和 `metadata` |
| 被测的问答链路 | Task：对每条数据运行一次的应用代码 |
| 代码评分器（Day26） | 在实验进程里运行的 evaluator 函数；也可以用平台托管的 code evaluator |
| 模型评审员（Day27） | LLM-as-a-Judge 评分器 |
| 一次评估运行（Day30、Day32） | Experiment run：任务在全部数据上执行一次，每条数据留下一条追踪 |
| 分数 | Score：有名字、值和数据类型（`NUMERIC`、`CATEGORICAL`、`BOOLEAN`、`TEXT`），可以挂在追踪、observation、会话或实验运行上 |
| 人工标注（Day24） | Annotation queue：需要先定义 score config，把追踪、observation 或会话放进队列，由领域专家逐条打分；标注结果也是校准模型评审员的依据 |
| 线上抽样打分（Day31） | 评分器加规则：规则用过滤条件和抽样比例选出新进入的数据，触发评分器 |

**分工：仓库是正本，平台是工作台**

| 放在仓库 | 放在平台 |
| --- | --- |
| 评估集 JSON 及其版本、`corpusDigest` | 每次实验的输出、追踪和分数 |
| 评分器代码和它的测试 | 实验之间的对比视图 |
| 基线结果和阈值（Day30） | 人工标注队列和标注结果 |
| 评审标准和校准记录（Day27） | 线上评分规则和告警 |

这样分的理由：评估集改动要像代码一样评审、能回溯，CI 不依赖平台也能运行；平台擅长的是存大量运行记录、对比和协作标注。平台上从线上追踪加入数据集的条目，或标注人在队列里确认的失败，要导出来走一次合入流程，进了仓库才算数。

**两种运行方式**

按当前文档，实验运行器既可以直接用进程里的本地数据，也可以用托管在平台上的数据集；两种结果都会出现在实验列表里。托管数据集多了共享的用例和历史版本（每次增、改、删条目都会产生一个以时间戳标识的版本）。

- 仓库为正本时，最简单的做法是每次直接从仓库读评估集，作为本地数据传进去。
- 想用平台上的数据集对比视图，就在评估集版本变化时同步一份上去，数据集名字带上版本，例如 `qa-golden/v3`（名字里的斜杠会显示为文件夹）。

**把 Day26 的评分器接进实验**

下面的代码按 Langfuse 文档“Experiments via SDK”一页的写法组织。`answer` 是你自己的问答链路，返回 Day26 约定的字典；`grade` 来自 Day26。

```python
import json
from langfuse import get_client, Evaluation
from graders import grade              # Day26 的评分器
from app import answer                 # 你的问答链路

langfuse = get_client()
golden = json.load(open("evals/golden-set.json", encoding="utf-8"))

data = [
    {"input": {"caseId": c["id"], "question": c["question"], "asUser": c.get("asUser")},
     "expected_output": c["expected"]}
    for c in golden["cases"]
]

def task(*, item, **kwargs):
    q = item["input"]
    return answer(q["question"], as_user=q["asUser"])

def code_grader(*, input, output, expected_output, **kwargs):
    checks = grade({"expected": expected_output}, output)
    failed = [f"{c.name}: 期望 {c.expected}，实际 {c.actual}" for c in checks if c.verdict != "pass"]
    return Evaluation(name="code_grader", value=0.0 if failed else 1.0,
                      comment="; ".join(failed) or "全部通过")

result = langfuse.run_experiment(
    name="qa-golden",
    run_name="prompt-v7",
    data=data,
    task=task,
    evaluators=[code_grader],
    metadata={"goldenSet": golden["schemaVersion"], "corpusDigest": golden["corpusDigest"]},
)
print(result.format())
```

要点：

- 评分明细写进 `comment`，在平台上点开某条用例就能看到期望和实际，和 Day26 的要求一致。
- 实验级的 `metadata` 会附在每条追踪上，用来记录 Day32 要求固定的那几项。
- 文档里的任务函数都返回字符串；本课让它返回字典，方便评分器直接读字段。如果你用的版本不接受字典，就返回 JSON 字符串，在评分器里再解析。
- 改用托管数据集时，先用 `langfuse.get_dataset(...)` 取出数据集，再调用它的 `run_experiment(...)`；这时任务函数通过 `item.input` 读取输入。

**还要决定的几件事**

- 实验里的 `asUser` 要照常传给检索，评估不绕过权限；追踪里有检索到的原文，平台上谁能看实验和标注队列，要和 Day21、Day69 的权限一致。
- 自托管还是使用托管服务，数据出域和保留期按 Day63 的规则定。
- 平台不可用时，CI 里的结构性回归（Day30）仍然要能只靠仓库运行。
