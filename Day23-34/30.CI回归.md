## Day30 - CI 回归

> 评估 ｜ 建议用时 1 小时

> **一句话**：把评估接进持续集成，让退步在合并之前就被拦住。
>
> **放在全局看**：这一步把评估从“偶尔跑一次的脚本”变成“每次改动必经的关卡”。它用替身模型替换 Day22 的 `answer()` 背后调用的 Day02 `chat()`，用 Day26 的评分器判定每条用例；Day32 的基线对比、Day33 的评估平台和 Day75 的发布流程都要调用这里定义的回归命令。

### 学习目标

- 设计一条能在持续集成里运行的评估命令。
- 定出让构建失败的阈值规则。

### 核心概念

**打个比方**：像体检和安检的区别：体检一年做一次，检查得仔细，对应定时触发的质量回归；安检每次进门都要过，检查得快而有限，只拦明显的问题，对应每次提交都跑的结构性回归。

**两层运行方式**

| 层 | 用什么模型 | 何时运行 | 检查什么 |
| --- | --- | --- | --- |
| 结构性回归 | 确定性的替身模型 | 每次提交 | 链路能跑通、引用格式合法、权限过滤生效 |
| 质量回归 | 真实模型 | 手动触发或定时 | 评估集上的真实分数 |

替身模型给出固定输出，让评估链路本身成为可测试的代码，不消耗模型额度，也不会因为模型波动让构建忽红忽绿。真实模型的评估单独触发，结果记录下来作为基线。

**替身模型：`FakeChat`**

替身模型顶替的是 Day02 的 `chat`：相同的调用方式（接收 `messages`，返回一个 `resp`，文本在 `resp.choices[0].message.content`），但不联网、不调用真实模型，按消息内容返回事先写好的输出。

```python
# tests/fake_chat.py
class FakeChat:
    """替身模型：按最后一条消息里的关键字返回固定输出，不调用真实模型。"""
    def __init__(self, fixtures: dict[str, str], default: str = "{}"):
        self.fixtures, self.default, self.calls = fixtures, default, []

    def __call__(self, messages, **kwargs):
        self.calls.append(messages)              # 记录每次调用，断言里可以检查是否被调用过
        last = messages[-1]["content"]
        text = next((v for k, v in self.fixtures.items() if k in last), self.default)
        message = type("Message", (), {"content": text})()
        choice = type("Choice", (), {"message": message})()
        return type("Response", (), {"choices": [choice]})()
```

用它替换 Day22 的 `answer()` 用到的模型调用，就能确定性地跑通整条链路。课程里的写法是 `from llm import chat`，导入之后 `answer` 模块持有自己的 `chat` 名字，所以要替换的是 `answer` 模块里的 `chat`，只改 `llm.chat` 不会生效：

```python
# tests/test_ci_regression.py
import answer as answer_mod             # Day22 的 answer.py
from fake_chat import FakeChat

def test_abstains_without_evidence(monkeypatch):
    fake = FakeChat({"完全没有涉及": '{"claims": []}'})
    monkeypatch.setattr(answer_mod, "chat", fake)   # 替换 answer 模块里用到的 chat
    result = answer_mod.answer("资料完全没有涉及的问题", groups={"public"})
    assert result.status == "abstained"
    # 检索为空时链路会在调用模型之前就弃答，所以这里不断言替身一定被调用过。
    # 要防止“悄悄连了真实模型”，在 CI 里不配置任何模型密钥即可：真实调用会直接报错。
```

用 `pytest tests/test_ci_regression.py -q` 跑这组测试。pytest 全部通过时进程退出码是 0；只要有一条断言失败，退出码就是非 0。CI 只需要看这条命令的退出码来决定这一步成败，不用解析输出文本。

**阈值怎么定**

- 回归集：任何一条从通过变成不通过都应拦住。和一个已确认的基线比较，比固定分数线更有用。
- 能力集：不设门槛，只记录趋势。
- 出现“错误内容”（例如引用了不存在的来源）和“没答出来”要区别对待，前者更严重。

**失败时要能定位**

评估输出应逐条列出：哪条用例、期望什么、实际得到什么。只给一个总分的评估，红了以后没人知道该修哪里。

### 动手练习

**20 分钟必做**

1. 写好 `FakeChat` 并接上 Day22 的 `answer()`，跑一遍 `pytest tests/test_ci_regression.py -q`（或等价的测试命令），确认测试通过、退出码是 0。
2. 让这条用例退化：故意改坏一处代码，例如让弃答判断总是返回 `answered`，重新跑同一条命令，确认至少一条断言失败、退出码变成非 0；改回来后再跑一次确认恢复通过。这就是“一条用例退化时构建失败”应有的样子。

**课后选做**

- 补一条检查“引用了未取回的片段”的回归测试，接 Day26 的 `grade`。
