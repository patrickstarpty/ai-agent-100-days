## Day26 - 代码评分器

> 评估 ｜ 建议用时 1 小时

> **一句话**：凡是能用代码判断对错的检查，都写成代码，让它逐条说清期望什么、实际得到什么。
>
> **放在全局看**：代码评分器是评估体系里最便宜、最稳定的一层。被测系统沿用 Day22 的 `answer()`。Day25 的评估集把期望写成了可检查的条件，这一课把这些条件变成函数；Day27 的模型评审员只接手代码判不了的部分，Day30 的 CI 回归直接调用这里的评分器。

### 学习目标

- 能按模板的用例格式，写出检查引用、关键字符串、弃答标记和受限来源的评分器。
- 能让评分器区分“没答出”和“答错”，并输出逐条明细。
- 会给评分器本身写测试。

### 核心概念

**打个比方**：像考试里的答题卡阅卷机：它只判涂没涂对，但判得又快又一致，还能打印出每道题错在哪。作文才交给老师。

**先问“代码能不能判”**

Day24 的失败分类表里，很多类别其实不需要模型判断：

| 失败类别 | 代码怎样判 |
| --- | --- |
| 没引用该引用的来源 | 比对 `mustCiteSources` 和回答里的引用 ID |
| 漏了关键事实 | 在回答里查找 `mustContain` 的短字符串 |
| 该弃答没弃答，或反过来 | 比对 `mustAbstain` 和输出里的弃答标记（Day17 要求弃答是显式字段） |
| 泄露了无权访问的来源 | 检查引用里是否出现 `mustNotCiteSources` |
| 引用了根本没取回的片段 | 比对引用 ID 和本次检索结果 |

剩下的“结论能不能从引用推出”“是否答非所问”，才交给 Day27 的评审员。

**没答出和答错要分开**

两种失败对用户的伤害不同。没答出，用户会去别处找；答错，尤其是引用了不存在或无权访问的来源，用户会带着错误信息继续工作。评分器给每项检查标三种结论之一：`pass`、`miss`（没答出）、`wrong`（答错），一条用例里只要有一项 `wrong`，整条就记为 `wrong`。所以一个回答给出了错误引用，比完全不给引用得到的结论更差。

**评分器示例**

被测系统沿用 Day22 的 `answer(question: str, groups: set[str]) -> AnswerResult`，`AnswerResult` 是 Day17 的 dataclass。评分器不直接读它，读的是一个字典：`answer`（结论文本拼接）、`citations`（引用的文档 ID）、`abstained`（是否弃答）、`retrieved`（本次检索取回的文档 ID）。两者之间由下一节的适配函数 `to_grader_output` 转换。

```python
from dataclasses import dataclass

@dataclass
class Check:
    name: str
    expected: object
    actual: object
    verdict: str          # "pass" | "miss"（没答出）| "wrong"（答错）

def norm(s: str) -> str:
    return "".join(s.split()).lower()   # 去掉空白、统一大小写

def grade(case: dict, out: dict) -> list[Check]:
    exp, cited = case["expected"], set(out.get("citations", []))
    checks = []
    if "mustAbstain" in exp:
        want, got = exp["mustAbstain"], out["abstained"]
        verdict = "pass" if want == got else ("wrong" if want else "miss")
        checks.append(Check("abstain", want, got, verdict))
    if "mustCiteSources" in exp:
        missing = sorted(set(exp["mustCiteSources"]) - cited)
        checks.append(Check("must_cite", exp["mustCiteSources"], sorted(cited),
                            "miss" if missing else "pass"))
    if "mustContain" in exp:
        absent = [s for s in exp["mustContain"] if norm(s) not in norm(out.get("answer", ""))]
        checks.append(Check("must_contain", exp["mustContain"], f"缺少 {absent}" if absent else "都出现了",
                            "miss" if absent else "pass"))
    if "mustNotCiteSources" in exp:
        leaked = sorted(set(exp["mustNotCiteSources"]) & cited)
        checks.append(Check("must_not_cite", f"不含 {exp['mustNotCiteSources']}", leaked,
                            "wrong" if leaked else "pass"))
    fabricated = sorted(cited - set(out.get("retrieved", [])))
    checks.append(Check("cited_were_retrieved", "引用都在取回结果里", fabricated,
                        "wrong" if fabricated else "pass"))
    return checks

def outcome(checks: list[Check]) -> str:
    verdicts = {c.verdict for c in checks}
    return "wrong" if "wrong" in verdicts else "miss" if "miss" in verdicts else "pass"
```

几个细节：该弃答却回答了记为 `wrong`，该回答却弃答记为 `miss`；`mustContain` 只放短而确定的字符串（数字、名称），比较前先规范化，避免“30天”和“30 天”被判成不同；`relation` 类用例的 `edges` 同样可以按（主体，关系，客体）三元组做集合比对，写法和 `must_cite` 一样。

**适配函数：从 `AnswerResult` 到评分器的字典**

`AnswerResult` 只有 `status`、`claims`、`reason`、`missing` 四个字段，结论里的证据是 E1、E2 这样的标签（Day16）。标签对应哪份文档、这次取回了哪些文档，要从同一次运行里拿。做法是让 Day22 的 `answer` 在返回前把这两样带出来：给 `AnswerResult` 增加两个有默认值的字段，`evidence`（本轮标签到 Day16 `Evidence` 的对照表）和 `retrieved_docs`（本轮取回的切片所属的文档 ID）。它们只供评估和追踪读取，Day17 里的其他用法不受影响。

```python
# graders.py，和 grade、outcome 放在一起
def to_grader_output(r: AnswerResult) -> dict:
    """把 Day22 的 answer() 返回值转成 grade() 读的字典。"""
    return {
        "answer": "\n".join(c.text for c in r.claims),
        "citations": sorted({r.evidence[label].doc_id
                             for c in r.claims for label in c.evidence}),
        "abstained": r.status == "abstained",
        "retrieved": sorted(set(r.retrieved_docs)),
    }

# 跑一条用例：case["groups"] 是提问人所属的组
out = to_grader_output(answer(case["question"], groups=set(case["groups"])))
checks = grade(case, out)
```

三种状态这样处理：

- `answered`：照常检查。
- `abstained`：`claims` 为空，于是 `answer` 是空串、`citations` 为空，`abstained` 为 `True`。
- `partial`：不算弃答，`abstained` 为 `False`，保留下来的结论照常参与 `mustContain`、`mustCiteSources` 等检查；没有依据的那部分列在 `r.missing` 里，评分器不读它。`answerable` 用例得到 `partial` 又缺了关键事实，记 `miss`；`should-abstain` 用例得到 `partial`，`abstain` 检查记 `wrong`，人工复核时再看那部分结论是否确有依据。

**输出明细，不只输出分数**

评估报告按用例逐行列出每个 `Check` 的 `name`、`expected`、`actual`、`verdict`，汇总时分别统计 `pass`、`miss`、`wrong` 的条数。看到“qa-001 must_cite 期望 doc-plan-standard，实际 []”，就知道该去查检索还是查生成，这正是 Day30 要求的“失败时能定位到用例”。

**评分器自己也要有测试**

评分器写错了，整套评估都会说假话。给每项检查准备手写的输出：一个应当通过，一个应当失败。

```python
QA = {"expected": {"mustCiteSources": ["doc-plan-standard"], "mustContain": ["30 天"], "mustAbstain": False}}
ACL = {"expected": {"mustNotCiteSources": ["doc-b"], "mustAbstain": True}}

def test_no_citation_is_miss_not_wrong():
    out = {"answer": "可在 30 天内退订。", "citations": [], "abstained": False, "retrieved": []}
    assert outcome(grade(QA, out)) == "miss"

def test_citation_not_retrieved_is_wrong():
    out = {"answer": "可在 30 天内退订。", "citations": ["doc-plan-standard", "doc-x"],
           "abstained": False, "retrieved": ["doc-plan-standard"]}
    assert outcome(grade(QA, out)) == "wrong"

def test_leak_is_wrong_even_when_abstained():
    out = {"answer": "", "citations": ["doc-b"], "abstained": True, "retrieved": ["doc-b"]}
    assert outcome(grade(ACL, out)) == "wrong"

def test_partial_counts_as_answer():
    ev = {"E1": Evidence("E1", "c-17", "doc-plan-standard", "第 2 节")}     # Day16
    r = AnswerResult(status="partial", claims=[Claim("标准套餐开通 30 天内可以退订。", ["E1"])],
                     missing=["跨境使用的说明"], evidence=ev, retrieved_docs=["doc-plan-standard"])
    assert outcome(grade(QA, to_grader_output(r))) == "pass"
```

这些测试不调用模型，可以放进每次提交的 CI。真实运行中发现评分器误判时，先把那条输出补成一个测试，再修评分器。
