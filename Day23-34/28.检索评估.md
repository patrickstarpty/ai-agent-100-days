## Day28 - 检索评估

> 评估 ｜ 建议用时 1 小时

> **一句话**：把“找资料”和“写回答”分开打分，才知道问题出在检索还是生成。
>
> **放在全局看**：检索是知识问答的上限（Day15）。这一课给 Day11~22 的检索链路配一把尺子，用它来比较 Day14 的混合检索和 Day15 的重排、上下文化检索，也为 Day32 的对比实验提供检索侧的指标。

### 学习目标

- 能说清为什么检索要单独评估，并用四格表定位失败。
- 会计算 recall@k 和 MRR，知道各自回答什么问题。
- 能用低成本的方法标注相关切片，并用它比较两种检索方案。

### 核心概念

**打个比方**：像查一道菜为什么难吃：先看采购买回来的菜对不对，再看厨师做得好不好。只尝最后那盘菜，分不清该换采购还是换厨师。

**分开评，才能定位**

端到端的评分（Day26）只告诉你回答对不对。把每条用例的检索结果单独判一次，就得到一张四格表：

| | 回答正确 | 回答错误 |
| --- | --- | --- |
| 检索取回了相关切片 | 正常 | 生成的问题：取回了但没用上，或用错了 |
| 检索没取回 | 碰巧答对或凭模型自身知识作答，要警惕 | 检索的问题：先修检索 |

右下格占多数时，先调提示词收效甚微；右上格占多数时，换检索方案也帮不上忙。

**两个指标**

- **recall@k**：标注为相关的切片里，有多少出现在前 k 条结果中。它回答“该找的找全了没有”。
- **MRR**（平均倒数排名）：每个问题取第一条相关结果的排名 r，记 1/r，没找到记 0，再对所有问题取平均。它回答“第一条有用的结果排得靠不靠前”。

```python
def recall_at_k(ranked: list[str], relevant: set[str], k: int) -> float:
    return len(set(ranked[:k]) & relevant) / len(relevant)

def reciprocal_rank(ranked: list[str], relevant: set[str]) -> float:
    for i, chunk_id in enumerate(ranked, start=1):
        if chunk_id in relevant:
            return 1 / i
    return 0.0
```

**小算例**

| 问题 | 检索结果（按排名） | 相关切片 | recall@3 | recall@5 | 倒数排名 |
| --- | --- | --- | --- | --- | --- |
| q1 | x, a, y, b, z | a, b | 1/2 | 1 | 1/2 |
| q2 | c, x, y, z, w | c | 1 | 1 | 1 |
| q3 | x, y, z, w, d | d | 0 | 1 | 1/5 |
| 平均 | | | 0.5 | 1.0 | MRR ≈ 0.57 |

recall@5 全满，说明东西都找到了；MRR 只有 0.57，说明排序还有空间，q3 的相关切片排在最后。这正是重排要解决的问题。

另一个常见指标 nDCG 允许相关性分等级（例如“直接回答”和“有帮助”），并按排名对靠后的结果打折扣，适合标注本身有等级的场合；二元标注够用时，前两个指标就够了。

**k 取多少，看评的是哪一段**

两段式检索（Day15）里，第一段负责不漏，看较大 k 的 recall，例如进入重排的候选数；第二段负责精选，看最终放进上下文的那几条的 recall 和 MRR。两段混在一起看，会把“没召回”和“没排上来”混为一谈。

**低成本地标注相关切片**

- **从已有期望出发**：评估集里的 `mustCiteSources` 已经标了来源文档，先在文档级算指标，不用逐个切片标。切片策略一变（Day12），切片 ID 就会变，文档级标注更耐用。
- **合并候选再判**：把几种检索方案各自的前 k 条合并去重，只让标注人判这个小池子里的切片相关与否。没进任何方案前 k 的切片，默认不相关。
- **二元判断**：只判“能不能用来回答这个问题”，不打分数（Day24）。
- **单独记录**：用 `should-abstain` 用例检查前几条结果的分数是否明显偏低；用 `must-not-appear` 用例检查结果里有没有受限来源，出现一次就判失败，不计入平均值（Day21）。

**用它比较方案**

固定同一批问题、同一份标注、同样的 k，比较下面几行，每行同时记录延迟和每次查询的成本：

| 方案 | 第一段 recall@候选数 | 最终 recall@k | MRR |
| --- | --- | --- | --- |
| 只用向量检索 | | | |
| 向量 + 关键词，RRF 融合（Day14） | | | |
| 再加重排（Day15） | | | |
| 上下文化切片 + 混合 + 重排（Day15） | | | |

上下文化检索要重建索引，比较时要确认两边用的是同一份语料版本（Day25 的 `corpusDigest`）。
