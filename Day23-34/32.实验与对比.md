## Day32 - 实验与对比

> 评估 ｜ 建议用时 1 小时

> **一句话**：在同一份评估集上一次只改一个地方，和记录下来的基线逐条对比，才能说清这次改动带来了什么。
>
> **放在全局看**：前面几课造好了尺子（Day25~29），这一课讲怎样用尺子做决定：换提示词、换模型、换检索方案，都按同一套实验方法来比。Day30 的 CI 回归用它定基线，Day75 的灰度发布在线上做同样的对比。

### 学习目标

- 能设计一次只改一个变量、有基线记录的对比实验。
- 能用重复运行和逐条翻转区分真实变化和噪声。
- 知道反复对着同一份评估集调参的风险，以及怎样防范。

### 核心概念

**打个比方**：像调一道菜的配方：每次只改一样调料，其余照旧，并且同一锅菜多尝几口再下结论。一次改了盐、糖和火候，就不知道是哪一样起了作用。

**固定什么，改什么**

一次实验里，下面这些要么全部固定，要么只改其中一项：

| 项目 | 记录什么 |
| --- | --- |
| 评估集 | 文件版本和 `corpusDigest`（Day25） |
| 提示词 | 版本号或内容摘要 |
| 模型 | 实际调用的模型和参数（Day70 要求记录实际使用的模型） |
| 检索配置 | 方案、k、是否重排、索引版本 |
| 代码 | 提交号 |

**先有基线**

基线是当前方案在当前评估集上的一次完整运行，保存每条用例的结果，而不只是总分。后面每次实验都和它逐条比较。评估集或语料变了，基线要重跑，否则分数变化里混着评估集本身的变化。

**波动从哪来，怎样量出来**

同样的配置跑两次，模型输出不同，个别用例会一次通过、一次不通过。量出波动最简单的方法：不做任何改动，把基线连续跑两三次，数一数有多少条用例结果不一致。这个数就是你这份评估集上的噪声水平。

```python
def flips(base: dict[str, bool], new: dict[str, bool]) -> dict[str, list[str]]:
    ids = sorted(base.keys() & new.keys())
    return {
        "fixed":  [i for i in ids if not base[i] and new[i]],   # 不通过 -> 通过
        "broken": [i for i in ids if base[i] and not new[i]],   # 通过 -> 不通过
    }

def flaky(runs: list[dict[str, bool]]) -> list[str]:
    ids = sorted(set.intersection(*(set(r) for r in runs)))
    return [i for i in ids if len({r[i] for r in runs}) > 1]   # 多次运行结果不一致
```

**不靠复杂统计，怎样判断是真变化**

- **看逐条翻转，不只看总分。** 总分不变，可能是修好了三条、又弄坏了三条。`broken` 里的每一条都要看。
- **和噪声比。** 改动带来的翻转条数，明显多于基线自己重跑时的翻转条数，才算信号。
- **剔除不稳定用例。** `flaky` 找出的用例，单次结果不能作为证据；它们要么多跑几次看通过率（Day29），要么检查是不是用例本身写得模糊。
- **看翻转集中在哪。** 改了检索，修好的用例应该集中在“检索没取回”那一类（Day28）；如果翻转散落在各类，更可能是噪声。

**比较三类改动时各看什么**

| 改动 | 除通过率外还要看 |
| --- | --- |
| 提示词 | `wrong` 和 `miss` 是否此消彼长，例如更敢答带来更多错答 |
| 模型 | 成本、延迟，以及评审员是否需要重新校准（Day27） |
| 检索设置 | recall@k、MRR（Day28），入库成本和查询延迟 |

**“调到评估集全过为止”的危险**

每看一次结果就改一次提示词，评估集上的分数会越来越高，但改动可能只是迎合了这几十条题目，换一批真实问题就不成立。防范的办法：

- 把评估集分成开发用和留出用两部分。日常实验只看开发部分；留出部分在决定上线前才跑一次，分数明显低于开发部分，就说明调过头了。
- 不断从线上失败补充新用例（Day31），让评估集跟着真实问题变化。
- 能力评估的通过率接近 100% 时，它已经提供不了改进方向，该补更难的用例了（Day23）。

### 动手练习

**20 分钟必做**

1. 不改任何东西，把主线项目的基线连跑三次，用 `flaky` 找出不稳定的用例，记下噪声水平。
2. 选一个改动（例如加一句弃答说明），只改这一处，跑一次，用 `flips` 列出修好和弄坏的用例，逐条看 `broken`。

**课后选做**

- 写一条结论：这次改动该不该保留，依据是哪几个数字和哪几条用例。

### 自检

1. 新提示词的总通过率比基线高了两条用例，你还需要看哪些信息才能决定采用它？
2. 为什么留出的那部分评估集只能在最后用一次？
