## Day37 - 状态与 Reducer

> 编排：工作流与受控循环 ｜ 建议用时 1 小时

> **一句话**：图里的节点只通过一份共享的状态交流，设计状态就是设计编排。
>
> **放在全局看**：状态决定了什么能被持久化（Day40）、被打断后恢复（Day41）、被实时推送（Day42）；Day38 的并行和子图也要靠它合并结果。

### 学习目标

- 为状态里的每个字段选定类型和 reducer。
- 预测两个并行节点同时写一个字段时，有 reducer 和没有 reducer 的结果分别是什么。

### 核心概念

**打个比方**：状态像一块大家共用的白板：每个节点看白板、做事、把结果写回去。reducer 是“两个人同时写同一栏时怎么办”的规矩。

**状态是唯一的共享数据**

LangGraph 的图围绕一个类型化的状态对象运行。节点读取状态、返回对状态的局部更新；边（包括条件边）根据状态决定下一个节点。节点之间不直接传参，一切经过状态。

**Reducer 决定更新怎样合并**

每个状态字段可以指定一个 reducer。没有 reducer 时，前后两步的写入是新值覆盖旧值；消息列表这类字段通常用“追加”的 reducer。并行节点在同一步里更新同一个字段时，由 reducer 决定怎样合并；没有 reducer，图会直接报错。

**状态里放什么**

| 应该放 | 不应该放 |
| --- | --- |
| 驱动路由的字段：任务类型、当前步数、等待原因 | 大块原文（放对象存储，状态里只留引用） |
| 预算计数：已用步数、token、时间 | 可以随时重新查询到的数据 |
| 版本标识：图版本、状态结构版本 | 密钥和令牌 |

状态会被写进检查点，所以它的大小直接影响持久化成本，它的结构变更直接影响旧任务能否恢复。给状态结构一个显式版本号，恢复时先比对版本。

**两个节点写同一字段：有没有 reducer 的区别**

没有 reducer 时，两个并行节点在同一步里都更新同一个字段，框架不知道该留哪一个，会抛出 `InvalidUpdateError`（官方错误页的代号是 INVALID_CONCURRENT_GRAPH_UPDATE）：

```python
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    tag: str   # 没有 reducer

def write_a(state: State) -> dict:
    return {"tag": "a"}

def write_b(state: State) -> dict:
    return {"tag": "b"}

builder = StateGraph(State)
builder.add_node("write_a", write_a)
builder.add_node("write_b", write_b)
builder.add_edge(START, "write_a")
builder.add_edge(START, "write_b")
builder.add_edge("write_a", END)
builder.add_edge("write_b", END)
graph = builder.compile()
graph.invoke({"tag": ""})   # 抛出 InvalidUpdateError：同一步里 tag 收到了两个值
```

把字段类型换成带 `operator.add` reducer 的列表，两边的写入会被合并：

```python
import operator
from typing import Annotated
from typing_extensions import TypedDict

class State2(TypedDict):
    tags: Annotated[list[str], operator.add]   # 有 reducer：追加合并

def write_a2(state: State2) -> dict:
    return {"tags": ["a"]}

def write_b2(state: State2) -> dict:
    return {"tags": ["b"]}

# 图结构同上，节点换成 write_a2 / write_b2，字段换成 tags
# graph2.invoke({"tags": []}) 得到 {"tags": ["a", "b"]}，两边都在，先后顺序不保证
```

两段的区别只在状态里那一行类型声明：没有 reducer 时并行写入直接报错，`operator.add` 时合并。报错比悄悄丢掉一边的结果好，问题在开发时就暴露出来；并行执行的顺序本身永远不保证，Day38 再细讲并行的事务性。
