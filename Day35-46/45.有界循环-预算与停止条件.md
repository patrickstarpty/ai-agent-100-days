## Day45 - 有界循环：预算与停止条件

> 编排：工作流与受控循环 ｜ 建议用时 1 小时

> **一句话**：agent 可以自己决定怎么做，但做多少步、花多少钱、用多久，由你的代码说了算。
>
> **放在全局看**：上限是 agent 能上生产的前提，也是成本可预测的来源。Day36 的 `stop_reason`、Day39 反思的轮数上限、Day42 界面显示的 `run_finished`，用的都是这里定义的停止原因；后面各阶段遇到新的停止场景，在这份枚举之上扩展，不再各写一套。

### 学习目标

- 为 agent 循环定出明确的上限。
- 设计一套用户和排查人员都能看到的停止原因，并知道整套课程共用的十个停止原因分别对应什么场景。

### 核心概念

**打个比方**：像给出差的同事定预算和返程日期：行程他自己安排，超了预算或到了日期就得回来汇报。

**四个上限**

一个可上线的 agent 循环至少有这四个上限：

| 上限 | 说明 |
| --- | --- |
| 步数 | 最多多少次“思考 → 调用工具 → 观察” |
| token | 一次任务累计可用的 token |
| 时间 | 在线任务的延迟预算，超出后转为后台任务或停止 |
| 工具调用 | 每类工具的调用次数上限，高风险工具更低 |

上限写在状态里（Day37），每一步检查，由代码裁决。模型可以建议“还需要再查一次”，是否允许由预算决定。

**停止原因要显式记录**

停止原因要用一个显式的枚举，不能靠解析回答文本来猜。本课程后面各处都引用下面这十个值，需要新的场景时在它之上扩展，并写明是扩展：

| 标识 | 中文含义 | 典型触发位置 |
| --- | --- | --- |
| `completed` | 完成 | 路由函数判断没有更多工具调用，或模型给出最终答案 |
| `max_steps` | 达到步数上限 | 步数计数节点，本课的核心上限 |
| `budget_exhausted` | 预算耗尽 | token 或时间预算检查节点 |
| `awaiting_human` | 等待人工 | 人工确认节点调用 `interrupt()` 之后（Day41） |
| `permission_changed` | 权限变更 | 恢复长任务时重新校验权限，发现已经变了（Day40） |
| `permission_denied` | 权限拒绝 | 工具调用前的权限校验，一开始就不具备权限 |
| `tool_failed` | 工具失败 | 工具调用节点捕获到异常且不可重试 |
| `version_incompatible` | 版本不兼容 | 用旧版本的检查点或计划恢复时，版本号比对不通过 |
| `cancelled` | 被取消 | 收到外部取消信号或用户主动终止 |
| `escalated` | 升级给人 | 规则判断风险或不确定性超出自动处理范围，转交给人 |

停止原因写进任务记录和追踪，界面上也要显示。达到上限时如实告知“已达到步数上限，以下是目前的结果”，不能把截断的结果当作完成。

**控制流属于你的代码**

《12-Factor Agents》里有三条与此直接相关：

- 掌握自己的控制流：循环、重试、暂停由你的代码决定，不交给框架的黑盒。
- 小而专注的 agent：范围小，上下文就短，行为就稳定。
- 把 agent 做成无状态的归约函数：给定当前状态和一个事件，返回新状态。状态在外部持久化，agent 本身可以随时重启。

**数值怎么定**

先从追踪数据里看真实任务用了多少步和多少 token，把上限定在覆盖绝大多数正常任务的位置，再留一点余量。上限定得过宽等于没有，过窄会让正常任务频繁被截断。定好之后，每个上限都要有一条测试证明它确实生效。

**预算检查的最小例子**

预算检查不需要任何框架，一个纯函数就够：输入已经用掉的量和上限，输出要不要停、停的原因是什么。

```python
from dataclasses import dataclass


@dataclass
class Budget:
    max_steps: int
    max_tokens: int


@dataclass
class Usage:
    steps: int = 0
    tokens: int = 0


def check_budget(budget: Budget, usage: Usage) -> str | None:
    """返回触发的停止原因；预算还够就返回 None。步数先判断，
    和 token 同时超限时，停止原因记为 max_steps。"""
    if usage.steps >= budget.max_steps:
        return "max_steps"
    if usage.tokens >= budget.max_tokens:
        return "budget_exhausted"
    return None


def test_check_budget_reports_max_steps_first():
    budget = Budget(max_steps=5, max_tokens=10000)
    usage = Usage(steps=5, tokens=20000)   # 两个上限都超了
    assert check_budget(budget, usage) == "max_steps"
```

路由函数（Day36 的 `route`）在每一步调用 `check_budget`，拿到的非空结果直接作为 `stop_reason` 写进状态，不需要再猜测或拼字符串。
