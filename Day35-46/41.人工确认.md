## Day41 - 人工确认

> 编排：工作流与受控循环 ｜ 建议用时 1 小时

> **一句话**：在不可逆的动作之前停下来等人点头，并让这个人看到足够的依据。
>
> **放在全局看**：人工确认建立在 Day40 的检查点之上，没有检查点 `interrupt()` 无法暂停；审批通过后以谁的身份执行见 Day59，审批记录会进入 Day62 的审计。

### 学习目标

- 掌握在图中暂停、等待人工输入、再恢复的机制。
- 为一条包含审批的流程设计关卡位置。

### 核心概念

**打个比方**：像公司的付款审批：经办人备好单据，金额大的要主管签字，签字的人要能看到合同和发票。

**暂停与恢复的机制**

`interrupt()` 要求图编译时带检查点（Day40），否则无法暂停。节点内调用 `interrupt()` 会暂停图的执行，状态经检查点保存，传入的值通过 `invoke()` 返回结果里的 `__interrupt__` 字段带给调用方。之后用同一个 `thread_id` 和 `Command(resume=...)` 再次调用，传入的值成为 `interrupt()` 的返回值。注意恢复时该节点从头执行，所以 `interrupt()` 之前的代码要能安全重跑。

```python
from typing_extensions import TypedDict
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import StateGraph, START, END
from langgraph.types import interrupt, Command

class State(TypedDict):
    change_summary: str
    approved: bool

def approval_node(state: State) -> dict:
    decision = interrupt({"action": "merge", "summary": state["change_summary"]})
    return {"approved": decision == "approve"}

builder = StateGraph(State)
builder.add_node("approval", approval_node)
builder.add_edge(START, "approval")
builder.add_edge("approval", END)
graph = builder.compile(checkpointer=InMemorySaver())

config = {"configurable": {"thread_id": "merge-1"}}
result = graph.invoke({"change_summary": "修复订单导出的日期过滤", "approved": False}, config=config)
print(result["__interrupt__"])          # 审批人看到的待审批内容，图停在这里

result = graph.invoke(Command(resume="approve"), config=config)
print(result["approved"])               # True，节点从头重跑，这次 interrupt() 直接拿到恢复值
```

**关卡设在哪**

人工确认是成本，放得太多流程就退化成人工流程。放在这些位置：

- 不可逆或难回滚的动作之前（合并、发布、对外发送）。
- 权限升级之前（从只读到可写）。
- agent 的产出将成为后续步骤的权威输入时（确认后的需求、发布的测试方案）。

**审批人看到什么**

审批请求应包含：要做什么、依据是什么、影响范围、可以修改的参数。只给“同意/拒绝”两个按钮而不给依据，审批会变成走过场。

**以谁的身份执行**

审批通过后的写操作，应以审批人或发起人的身份和权限执行，agent 本身不持有写权限。这样审计记录里每个变更都能对应到一个人。
