## Day41 - 人工确认

> 编排：工作流与受控循环 ｜ 建议用时 1 小时

> **一句话**：在不可逆的动作之前停下来等人点头，并让这个人看到足够的依据。
>
> **放在全局看**：人工确认是 agent 的自主性和可控性之间的调节阀。

### 学习目标

- 掌握在图中暂停、等待人工输入、再恢复的机制。
- 为一条包含审批的流程设计关卡位置。

### 核心概念

**打个比方**：像公司的付款审批：经办人备好单据，金额大的要主管签字，签字的人要能看到合同和发票。

**暂停与恢复的机制**

在 LangGraph 里，节点内调用 `interrupt()` 会暂停图的执行，状态经检查点保存，传入的值返回给调用方（例如“待审批的内容”）。之后用同一个线程 ID 和 `Command(resume=...)` 再次调用，传入的值成为 `interrupt()` 的返回值。注意恢复时该节点从头执行，所以 `interrupt()` 之前的代码要能安全重跑。

```python
from langgraph.types import interrupt, Command

def approval_node(state):
    decision = interrupt({"action": "merge", "summary": state["change_summary"]})
    return {"approved": decision == "approve"}

# 恢复：graph.invoke(Command(resume="approve"), config={"configurable": {"thread_id": tid}})
```

**关卡设在哪**

人工确认是成本，放得太多流程就退化成人工流程。放在这些位置：

- 不可逆或难回滚的动作之前（合并、发布、对外发送）。
- 权限升级之前（从只读到可写）。
- agent 的产出将成为后续步骤的权威输入时（确认后的需求、发布的测试方案）。

**审批人看到什么**

审批请求应包含：要做什么、依据是什么、影响范围、可以修改的参数。只给“同意/拒绝”两个按钮而不给依据，审批会变成走过场。

**以谁的身份执行**

审批通过后的写操作，应以审批人或发起人的身份和权限执行，agent 本身不持有写权限。这样审计记录里每个变更都能对应到一个人。
