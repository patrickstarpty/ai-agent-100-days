## Day35 - 工作流还是 Agent

> 编排：工作流与受控循环 ｜ 建议用时 1 小时

> **一句话**：步骤能事先写清楚就用工作流，写不清楚才用 agent。
>
> **放在全局看**：这是架构师最常被问到的判断。Day36 起学的 LangGraph 把工作流落成图，Day44 的规划、Day45 的上限都要先过这一步判断，才知道该管多细。

### 学习目标

- 能判断一个任务该用固定工作流还是自主 agent。
- 把自己项目里的任务逐个归类。

### 核心概念

**打个比方**：工作流像流水线，每个工位做什么是定好的；agent 像一位自己安排工作的师傅。流水线便宜稳定，师傅灵活但贵。

**两个概念的界线**

- 工作流：模型和工具按预先写好的代码路径被编排。步骤由你决定。
- Agent：模型自己决定下一步做什么、用哪个工具、何时停止。步骤由模型决定。

多数生产系统处在两者之间。原则是用能可靠满足需求的最低复杂度：一次模型调用能解决就不用工作流，工作流能解决就不用 agent。

**五种常见的工作流模式**

| 模式 | 做法 |
| --- | --- |
| 提示链 | 上一步的输出是下一步的输入，步骤之间可加检查 |
| 路由 | 先分类，再交给对应的专门处理 |
| 并行 | 拆成互不依赖的子任务同时做，或同一任务做多次取共识 |
| 编排者与工作者 | 一个模型拆任务并分派，再汇总结果 |
| 评估者与优化者 | 一个生成，一个评审并反馈，循环到达标 |

其中“评估者与优化者”的最小形式是反思，Day39 专门讲。让模型自己制定步骤的规划模式在 Day44。

**两个独立的维度**

“跑得久”和“推理复杂”不是一回事，建议分开记录：

- 执行方式：在线立即完成，或后台持久执行（可暂停、恢复、取消）。
- 推理方式：直接生成、固定工作流，或有上限的 agent 循环。

文档解析耗时很长，但每一步都是确定的，属于“持久执行 + 固定工作流”。把它塞进 agent 循环只会增加成本和不确定性。

### 动手练习

**20 分钟必做**

1. 列出主线项目的所有 AI 任务，每个标注执行方式和推理方式，并标出哪些不应进入 agent 循环。

**课后选做**

2. 对案例 B（AI 原生研发流程），把“需求工单 → 需求优化 → 审批 → 编码 → 提交 → 构建 → 发布”的每一步标为确定性步骤或 agent 步骤。通常会发现，真正需要 agent 的只有“需求优化”和“编码”两步，其余是普通的流水线加审批关卡。

### 自检

1. 说出一个你见过的、本该用工作流却做成了 agent 的例子。
2. 路由模式里，分类这一步用模型还是用规则，各自的风险是什么？
