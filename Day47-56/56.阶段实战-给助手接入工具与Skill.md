## Day56 - 阶段实战：给助手接入工具与 Skill

> 工具、Skills 与 MCP ｜ 建议用时 1 小时

> **一句话**：给 Day10 的命令行助手换上注册表和白名单，接入一个 MCP server，导入一个 Skill，并用测试证明名单外的工具会被拒绝。
>
> **放在全局看**：这是本阶段的试验台。做完之后，助手的每个能力都有登记、有边界、有版本，Day57~66 的安全阶段会在这个基础上做威胁建模和权限收紧。

### 学习目标

- 把 Day48~55 的做法组合进一个能运行的助手。
- 用一份验收清单逐条检查，尤其是“名单外的工具不执行”“Skill 里的代码不执行”这两条边界。

### 核心概念

**需求**

| 功能 | 要求 | 对应课程 |
| --- | --- | --- |
| 注册表 | `calculate`、`read_file` 改写为 `ToolSpec` 并登记；发给模型的工具定义全部由注册表生成 | Day48 |
| 白名单 | agent 定义列出可用工具；分发前检查白名单、权限和调用上限，不满足就不执行，拒绝原因作为工具结果返回 | Day48 |
| 错误处理 | 参数错误交还模型；只读工具的瞬时错误有限次重试；权限拒绝结束本轮并告知用户 | Day49 |
| MCP | 以 stdio 接入 Day51 的课程目录 server；只登记评审过的工具，名字加 `catalog_` 前缀 | Day50、Day51 |
| Skill | 导入一个 Skill，生成以内容哈希为编号的修订；系统提示词里只放目录，用 `load_skill` 按需读取 | Day53、Day54 |
| 代码不执行 | 导入和运行时都不执行 Skill 里的脚本 | Day54 |
| Agent 定义 | 一个定义文件写明系统提示词、Skill 修订、工具白名单、模型别名；启动时校验 | Day55 |

```python
# mcp_bridge.py
from mcp import Client

async def register_mcp_tools(client: Client, registry, server: str, reviewed: dict[str, dict]) -> list[str]:
    """把 server 的工具登记进注册表，返回登记成功的工具名。

    - 用 client.list_tools() 发现工具，tool.name / tool.description / tool.input_schema
      对应 ToolSpec 的名称、描述和参数结构。
    - 只登记出现在 reviewed 里的工具；只读或写、风险、上限、权限取自 reviewed，不取自 server。
    - 工具名加上 server 前缀；func 内部调用 client.call_tool，把文本内容拼起来，
      is_error 为真时按工具执行错误交还模型。
    """
    ...
```

```python
# tests/test_allowlist.py
from types import SimpleNamespace

def test_tool_outside_allowlist_is_refused():
    called = []
    registry = build_registry()                       # 自己实现：登记本地工具
    registry.register(make_spec("files_delete", func=lambda **kw: called.append(kw) or "deleted"))
    call = SimpleNamespace(id="c1", function=SimpleNamespace(
        name="files_delete", arguments='{"path": "notes.txt"}'))

    result = dispatch(call, registry, allowed={"calculate", "read_file"}, ctx=fake_ctx())

    assert called == []                               # 函数没有被调用
    assert "files_delete" in result                   # 拒绝原因说明了是哪个工具
```

这条测试的关键在于：`files_delete` 已经登记在注册表里，模型也“要了”它，但它不在这个 agent 的白名单里，所以不执行。

**三个容易做错的地方**

同步循环和异步 client。官方 Python SDK 的 MCP client 是异步的，`async with Client(...)` 管理整个连接，进入时启动 server 进程，退出时关闭。最省事的做法是把 `run_turn` 改成异步，整个会话只开一个连接；每次调用都新建连接也能用，但每次都要启动一个进程。

MCP 工具的元数据从哪里来。server 返回的只有名称、描述和参数结构。只读或写、风险级别、所需权限必须来自你们自己的评审文件。server 新增了一个工具，评审文件里没有它，它就不进注册表，更不进白名单。

Skill 修订和 agent 定义的对应。导入后得到的是修订号，agent 定义要写修订号，不能只写名字。重新导入一个改过的 Skill 后，定义里的修订号不变，agent 的行为也不该变；要用新修订，就发布一个新的 agent 定义。相应地，`skill_catalog` 和 `load_skill` 要按定义里的修订号去 `skills/<name>/<revision>/` 下读取，不能读“最新的那份”。

### 动手练习

按上面的结构实现。先写 `tests/test_allowlist.py` 和 `cases.md`（验收问题和期望行为），再写代码，最后逐条验证。

**验收清单**

注册表与白名单

- [ ] 代码里没有手写的工具定义列表，发给模型的定义全部由 `registry.schemas_for(...)` 按白名单生成。
- [ ] 注册表里每个工具的九个字段齐全；注册同名工具时报错。
- [ ] `test_tool_outside_allowlist_is_refused` 通过：名单外的工具不执行，拒绝原因作为 tool 消息返回，循环继续。
- [ ] 另有两条测试通过：无权限的用户被拒绝；超过调用上限被拒绝。
- [ ] 每次拒绝都在日志里留下一行，包含工具名和拒绝原因。

错误处理

- [ ] 让 `read_file` 的前一次调用抛出瞬时错误：自动重试一次后正常回答，日志有重试记录。
- [ ] 模拟一次权限拒绝：本轮结束，输出标明停止原因，模型没有改用其他工具去拿同样的数据。

MCP

- [ ] 启动时连接 Day51 的 server，打印登记成功的工具，名字是 `catalog_courses_search`。
- [ ] 在 server 里加第二个工具但不写进评审文件：它没有进入注册表。
- [ ] 问“有哪些 Python 课程”，进度输出显示调用了 `catalog_courses_search`，回答与 server 数据一致。
- [ ] 让 server 的工具参数越界：模型收到错误文本并调整参数或如实说明。
- [ ] server 无法启动时，助手给出清楚的提示，本地工具照常可用。

Skill

- [ ] 从 `incoming/` 导入一个 Skill，得到修订号；改动一个字再导入，得到不同的修订号，旧修订仍可读取。
- [ ] 在 Skill 目录里放一个脚本，让它一旦运行就创建一个标记文件。导入并使用这个 Skill 之后，标记文件不存在，导入结果里列出了这个脚本。
- [ ] 系统提示词里只有 Skill 的名称和简介；问一个相关问题时调用了 `load_skill`，问无关问题时没有调用。

Agent 定义

- [ ] 定义里写的是 Skill 的修订号和模型别名，没有步数上限、没有密钥。
- [ ] 把一个未注册的工具名写进定义：启动校验失败，并指出是哪一个工具。
