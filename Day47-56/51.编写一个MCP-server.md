## Day51 - 编写一个 MCP server

> 工具、Skills 与 MCP ｜ 建议用时 1 小时

> **一句话**：MCP server 就是一个按协议回答“有哪些工具”和“调用这个工具”两种请求的程序，最小的版本几十行就够。
>
> **放在全局看**：Day50 讲了 MCP 的角色和传输，这一课亲手写一个只读的 server，再用 client 发现并调用它。Day52 给远端 server 加上认证，Day56 把它接进命令行助手的注册表。

### 学习目标

- 用官方 Python SDK 写出一个只暴露一个只读工具的 server，用 stdio 运行。
- 看懂 client 和 server 之间 `tools/list`、`tools/call` 两组 JSON-RPC 消息。
- 会用 MCP Inspector 在本地调试 server。

### 核心概念

**打个比方**：像在小区门口开一个代收点：门口贴一张服务清单（`tools/list`），来人照清单报业务和材料（`tools/call`），代收点按规矩办完回一张回执。清单写得清楚，来的人就不会报错业务。

**先核对版本**

撰写时 MCP 的协议版本是 `2026-07-28`，官方 Python 快速上手要求 SDK 2.0.0 及以上。这一版和很多旧教程不同：SDK 里旧的 `FastMCP` 改名为 `MCPServer`；协议改为无状态，每个请求在 `_meta` 里自带协议版本和 client 能力声明，server 不能依赖同一连接上之前的请求。SDK 会替你处理这些字段。动手前请再打开一次官方快速上手，以当时的版本为准。

**最小的 server**

一个课程目录查询服务，只有一个只读工具：

```python
# course_server.py
import logging

from mcp.server import MCPServer

logging.basicConfig(level=logging.INFO)    # 默认写到 stderr
logger = logging.getLogger(__name__)

mcp = MCPServer("course-catalog")

COURSES = {
    "PY101": {"title": "Python 入门", "hours": 12, "seats_left": 5},
    "DB201": {"title": "数据库基础", "hours": 16, "seats_left": 0},
}

@mcp.tool()
def courses_search(keyword: str, limit: int = 5) -> str:
    """按关键词查询课程目录，返回课程编号、名称、课时和剩余名额。只读，不会报名。

    Args:
        keyword: 课程名称里的关键词，例如 Python
        limit: 最多返回几条，1 到 20
    """
    if not 1 <= limit <= 20:
        raise ValueError(f"limit 应在 1 到 20 之间，收到的是 {limit}")
    logger.info("courses_search keyword=%s", keyword)
    hits = [f"{cid} {c['title']}，{c['hours']} 课时，剩余名额 {c['seats_left']}"
            for cid, c in COURSES.items() if keyword.lower() in c["title"].lower()]
    if not hits:
        return f"没有找到名称包含“{keyword}”的课程，可以换一个更短的关键词再试。"
    return "\n".join(hits[:limit])

if __name__ == "__main__":
    mcp.run(transport="stdio")
```

按快速上手的做法建项目：`uv init`、`uv add "mcp[cli]"`，然后 `uv run course_server.py` 启动。对照代码注意四点：

- 工具定义由函数名、类型注解和 docstring 自动生成，docstring 就是给模型看的描述，按 Day47 的要求写。
- “没找到”作为正常结果返回，附上下一步建议；参数越界则抛出异常。按官方 client 教程的说明，server 端工具抛出异常时，client 那边不会抛出异常，收到的是 `is_error` 为真的结果，模型可以读到错误再调整（Day49）。
- stdio server 绝不能往 stdout 写东西，`print()` 会破坏 JSON-RPC 消息。日志一律走 stderr。
- 这个 server 没有任何写操作，所以不需要确认和幂等。第一个 server 从只读开始，风险最小。

**线上的消息长什么样**

client 发现工具时发 `tools/list`（下面省略了每个请求都必须带的 `_meta`，规范页面的示例也是这样省略的）：

```json
{"jsonrpc": "2.0", "id": 1, "method": "tools/list", "params": {}}
```

server 返回工具列表，大致是：

```json
{"jsonrpc": "2.0", "id": 1, "result": {
  "resultType": "complete",
  "tools": [{
    "name": "courses_search",
    "description": "按关键词查询课程目录，返回课程编号、名称、课时和剩余名额。只读，不会报名。...",
    "inputSchema": {"type": "object",
                    "properties": {"keyword": {"type": "string"}, "limit": {"type": "integer"}},
                    "required": ["keyword"]}
  }]
}}
```

SDK 实际生成的 schema 可能多几个字段，以 Inspector 里看到的为准。调用时发 `tools/call`：

```json
{"jsonrpc": "2.0", "id": 2, "method": "tools/call",
 "params": {"name": "courses_search", "arguments": {"keyword": "Python"}}}
```

结果放在 `content` 里，`isError` 标明是否为工具执行错误：

```json
{"jsonrpc": "2.0", "id": 2, "result": {
  "resultType": "complete",
  "content": [{"type": "text", "text": "PY101 Python 入门，12 课时，剩余名额 5"}],
  "isError": false
}}
```

**client 怎样发现并调用它**

按官方 client 教程的写法：

```python
import asyncio

from mcp import Client, StdioServerParameters
from mcp.client.stdio import stdio_client
from mcp_types import TextContent

async def main() -> None:
    params = StdioServerParameters(command="python", args=["course_server.py"])
    async with Client(stdio_client(params)) as client:      # 进入时启动 server，退出时关闭
        listed = await client.list_tools()
        for tool in listed.tools:
            print(tool.name, tool.input_schema)
        result = await client.call_tool("courses_search", {"keyword": "Python"})
        text = "\n".join(b.text for b in result.content if isinstance(b, TextContent))
        print("is_error:", result.is_error)
        print(text)

asyncio.run(main())
```

`tool.name`、`tool.description`、`tool.input_schema` 正好对应 Day05 工具定义里的名称、描述和参数结构，转换一下就能放进注册表（Day48），这是 Day56 要做的事。

**本地调试**

- MCP Inspector 是官方的调试工具，需要 Node 22.19.0 或更新的版本。把启动 server 的命令跟在后面即可：`npx @modelcontextprotocol/inspector uv run course_server.py`，会打开一个浏览器界面，可以列出工具、填参数调用、查看来回的 JSON-RPC 消息。
- 命令行模式适合写进脚本：`npx @modelcontextprotocol/inspector --cli uv run course_server.py --method tools/list`。
- SDK 仓库的 README 还给了另一种启动方式：`uv run mcp dev course_server.py`。
- server 的日志在 stderr。工具没被发现时，先看 stderr 有没有报错；工具调用失败时，用 Inspector 单独调一次，排除模型和 client 的干扰。
