## Day100 - 持续学习与路线更新

> 架构师收口 ｜ 建议用时 1 小时

> **一句话**：产品名、API、协议版本和模型能力很快会过时，评估、权限、上限、确定性门禁和清晰的契约老得很慢；把核对新版本变成例行工作，把课程的产出变成团队自己维护的知识库。
>
> **放在全局看**：这是最后一课。前面留下的决策记录（Day95 讲了怎样写好）、评估集和历史任务集（Day25、Day90）、威胁模型（Day66、Day93）、参考架构（Day96）和评审清单（Day97），从今天起要靠你和团队维护下去。

### 学习目标

- 分清课程里哪些内容老得快、哪些老得慢，并知道各自怎样跟进。
- 定下几条跟进新版本的例行做法和触发条件。
- 把课程产出整理成团队的知识库。

### 核心概念

**打个比方**：像城市里的地图和交通规则：店铺、公交线路年年在变，地图要常常更新；靠右行驶、红灯停这些规则很多年都不变，学会了一直有用。

**老得快的和老得慢的**

| 老得快 | 课程里的例子 | 老得慢 | 课程里的例子 |
| --- | --- | --- | --- |
| 产品名与预览功能 | Day91 的编码 agent 产品处于公开预览，会话时长等限制随时可能调整 | 评估 | 固定任务、评分器、基线对比（Day23、Day30） |
| 框架和 SDK 的 API | LangGraph、Langfuse 的接口写法（Day36、Day33） | 权限 | 按提问人过滤、写操作以用户身份执行（Day21、Day59） |
| 协议版本 | 撰写时 MCP 的协议版本是 2026-07-28，协议改为无状态，sampling 被标为弃用，旧教程里的写法已不适用（Day50） | 上限 | 步数、token、时间、工具调用四个上限（Day45） |
| 模型能力与价格 | 哪个模型擅长什么、多少钱 | 确定性门禁 | 模型提议，规则和人放行（Day65、Day92） |
| 平台的功能边界 | 哪些权限过滤是正式功能、哪些仍是预览（Day21） | 清晰的契约 | 类型化的输入输出、带状态的结果（Day80） |

左边一列决定你“怎么写代码”，右边一列决定你“系统该长什么样”。左边过时了要改实现，右边几乎不需要改。读到一篇新文章或一个新产品时，先看它属于哪一列：属于左边，就核对它是否替代了你现在的某个选择；属于右边，就看它有没有挑战你已有的原则。

**跟进的例行做法**

| 时机 | 做什么 |
| --- | --- |
| 每个阶段或项目开始前 | 打开用到的框架、SDK、协议的官方文档，核对版本和接口，在文档里记下核对日期 |
| 换模型、升级 SDK、改提示词之后 | 重跑评估集和历史任务集，和基线逐条比较（Day30、Day32、Day90） |
| 决策记录的“重新评估”条件出现时 | 重新评估那个决定；结论变了就写一份新记录取代旧的（Day95） |
| 用到的预览功能转为正式版或被下线时 | 回看依赖它的设计和决策记录 |
| 定期 | 检查文档里的外部链接是否还有效、内容是否变了；复查评审清单有没有该加的问题 |

关键是“核对日期”和“触发条件”。一份写着“撰写时”和核对日期的文档，读者知道它可能过时、该去哪里核对；一份没写日期的文档，读者只能全信或全不信。

**把课程产出变成团队的知识库**

一百天下来，你手里应该有这些东西：

- 决策记录（Day34、Day66、Day73、Day76、Day94 各产出过，Day95 练习里也写过一份）和一页参考架构（Day96）。
- 评估集和历史任务集，以及跑它们的命令（Day25、Day90）。
- 威胁模型和技术栈映射表（Day66、Day76、Day93）。
- 设计评审清单（Day97），以及 Day98、Day99 写出的评审报告。

把它们放进一个团队共用的仓库，按上面的类别分目录，每份文档写明负责人和最近一次核对日期。评审中发现的新问题回流到清单里，事故复盘的结论写成决策记录或评估用例。

最后可以把这个仓库本身接入案例 A 的企业知识库：团队成员和 agent 都能检索它，检索照样按权限过滤，回答照样带引用。

### 动手练习

**20 分钟必做**

1. 把你在本课程中写下的所有文档列成一张清单，每份标上类别、负责人、最近一次核对日期，以及它依赖的“老得快”的内容。
**课后选做**

1. 挑出三份决策记录，确认它们的“重新评估”条件都写成了能被观察到的事件，写得含糊的改写一遍。
2. 定一个日期，到那天重跑一次评估集，并核对一遍用到的框架文档。

### 自检

1. 你的主线项目里，哪一个设计选择最依赖“老得快”的内容？它过时的时候你会怎样发现？
2. 为什么文档里要写明核对日期，而不只写“以官方文档为准”？
