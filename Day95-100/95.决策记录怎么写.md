## Day95 - 决策记录怎么写

> 架构师收口 ｜ 建议用时 1 小时

> **一句话**：把一个跨模块、难回头的决定写成一页：背景、一句能被检验的决定、认真比较过的方案、连同代价在内的后果。
>
> **放在全局看**：前面每个阶段复盘（Day34、Day66、Day76、Day94）都产出了决策记录，Day96 的参考架构是它们的汇总入口。这一课讲怎样把它们写好。

### 学习目标

- 判断一个决定值不值得写成决策记录。
- 把决定写成可检验的陈述，并写出没选的方案和真实的代价。
- 用 [决策记录模板](../模板/决策记录模板.md) 写完一份。

### 核心概念

**打个比方**：像棋谱上的注释：棋谱只记下走了哪一步，注释写明当时为什么这么走、还考虑过哪一步、为什么没走。几年后复盘，有注释的那盘棋才看得懂。

**什么值得写**

格式来自 Michael Nygard 2011 年的文章《Documenting Architecture Decisions》。他建议记录那些影响结构、非功能特性、依赖、接口或构建方式的决定。落到 agent 项目上，用两个条件筛选：

- **跨模块。** 不止一个团队或组件要照着做，例如“写操作以用户身份执行”。
- **难回头。** 改起来要迁移数据、重建索引、改很多调用方，例如选哪种追踪格式。

单个提示词的措辞、一个函数怎么命名，这类局部且容易改的事不必写。写得太多，真正重要的那几份会被淹没。

**把决定写成可检验的陈述**

| 写法 | 问题 |
| --- | --- |
| 尽量使用开放标准做追踪 | “尽量”无法检验，任何做法都能说自己尽量了 |
| 所有 span 以 OTLP 导出；业务代码不直接调用追踪平台的 SDK | 可以用代码搜索或 CI 规则检查 |

写完后只读“决定”这一节，读者应该知道自己该怎么做，评审人应该能判断某段代码是否违反了它。

**写清没选什么**

“考虑过的方案”里要放真正纠结过的那个，不要摆一个明显不行的方案来陪衬。没采用的原因写到本项目的具体约束上，例如“需要按项目设置保留期，而该方案只支持全局设置”。半年后有人提议换方案，这一节能直接告诉他上次为什么没选。

**后果要写出代价**

后果分三部分：变容易的事、变难的事或新增的约束、什么情况出现时重新评估。Nygard 也强调所有后果都要列出，不能只写正面的。只有好处的记录，通常说明还没想清楚。“重新评估的触发条件”要写成能被观察到的事件，例如“追踪平台不再支持按项目设置保留期”，Day100 的例行检查就靠它。

**只用一个状态字段**

模板里只有一个状态：提议、已接受、已被取代。不要再加“是否生效”“审批进度”之类的字段，几个字段一旦互相矛盾，读者就不知道该信哪个。已接受的记录不回头修改结论；决定变了就写一份新的，把旧的标为“已被取代”并写明被哪份取代，旧记录留着，它记下了当时的理由。

**一个简短的示例**

```markdown
# 决策 007：追踪数据存放在追踪平台，业务库只保存 trace ID

- 状态：已接受
- 日期：2026-10-10
- 相关课程：Day62、Day63、Day69

## 背景

追踪里有提示词和回答的原文，需要设置保留期并限制读取人。审计记录是业务记录，
保留期和读者都不同，需要能从审计记录找到对应的追踪。

## 决定

所有 trace 只写入追踪平台；业务库的审计表只保存 trace ID，不保存任何追踪内容。

## 考虑过的方案

| 方案 | 优点 | 没有采用的原因 |
| --- | --- | --- |
| 追踪也写进业务库 | 查询方便，一个地方看全 | 追踪的保留期和读取权限无法与审计记录分开管理 |

## 后果

- 变容易：追踪按自己的保留期清理，不影响审计记录。
- 变难：排查时要在两个系统之间跳转；追踪被清理后，旧审计记录的 trace ID 会失效。
- 重新评估：追踪平台不再支持按项目设置保留期，或审计要求保留追踪原文时。
```

### 阅读材料

- Michael Nygard [Documenting Architecture Decisions](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions)（2011 年 11 月）

### 动手练习

1. 从你的主线项目里挑一个最近做的、符合“跨模块、难回头”的决定，用模板写一份，控制在一页内。
2. 写完后按模板末尾的三个问题自查，再请一位同事只读“决定”一节，说出他会怎么做。

### 自检

1. “检索结果尽量按权限过滤”这句决定有什么问题，怎样改写才能被检验？
2. 一个已接受的决定后来被推翻，为什么要新写一份，不直接修改原来那份？
