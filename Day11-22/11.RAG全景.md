## Day11 - RAG 全景

> 知识检索 ｜ 建议用时 1 小时

> **一句话**：RAG 就是先从你的资料里找出相关的几段，再让模型只依据这几段回答，并标明每句话出自哪里。
>
> **放在全局看**：这是本阶段的地图。Day12~21 各讲链路上的一环，Day22 把它们装成一条完整的带引用问答；评估阶段的 Day28 会把检索和生成分开度量。

### 学习目标

- 能画出 RAG 的完整链路，说清每一环的输入、输出和常见失败。
- 能判断一个场景该用检索，还是直接把整篇文档放进上下文。
- 回答出错时，知道按什么顺序排查是哪一环的问题。

### 核心概念

**打个比方**：像开卷考试：先翻书找到相关的几页（检索），再照着这几页写答案（生成），最后在每句话后面注上页码（引用），阅卷老师可以逐条翻书核对。

**两半链路**

RAG 分成入库和查询两半。入库在后台离线完成，查询在每次提问时在线完成。

```text
入库：原始文件 → 解析 → 切片 → 建索引（向量、关键词、图谱）
查询：问题 → 检索（按权限过滤）→ 重排 → 生成（带证据编号）→ 引用校验 → 回答或弃答
```

| 环节 | 做什么 | 典型失败 | 对应课程 |
| --- | --- | --- | --- |
| 解析 | 把 PDF、DOCX、表格等变成带位置信息的文本 | 扫描件没有文字层，内容静默丢失；表格被打散 | Day12 |
| 切片 | 把长文本切成可检索的小段 | 一条规则被切成两半；切片丢了“这是哪个套餐”的背景 | Day12、Day15 |
| 索引 | 为切片建向量索引和关键词索引 | 换了 embedding 模型却没有重建索引 | Day13、Day14 |
| 检索 | 按问题取回候选切片 | 套餐编号、产品型号这类精确词查不到 | Day13、Day14、Day21 |
| 重排 | 从几十个候选里精选几条 | 正确的切片取回了，却被排到截断线之外 | Day15 |
| 生成 | 模型依据编号的证据写结论 | 结论超出证据，或混入模型自己的常识 | Day16 |
| 引用校验 | 用代码检查每条引用是否合法 | 引用了不存在的编号，或没有权限的切片 | Day16 |
| 弃答 | 证据不足时明确不答 | 资料里没有，模型仍然编了一个答案 | Day17 |

权限过滤写在检索这一格里，是因为它必须发生在查询时，无权内容不进上下文（Day21）。检索回来的文档也是外来文本，里面可能藏着像指令的话（Day58），所以给模型的证据要和指令分开放。

**什么时候直接放整篇文档**

检索本身也会出错，链路越长，出错的地方越多。资料少的时候，可以跳过检索，把整份资料放进上下文。Anthropic 在介绍上下文化检索的文章里给过一个参考：知识库小于约 20 万 token 时，可以直接把全部内容放进提示词，并配合提示缓存降低重复发送的成本。这个数字依赖模型的窗口和价格，按你用的模型和 Day07 的成本估算重新算。

| 倾向直接放进上下文 | 倾向检索 |
| --- | --- |
| 一两份文档，例如一本课程手册 | 几百上千份文档，持续增加 |
| 内容很少变化 | 每天都有更新 |
| 所有用户看到的内容相同 | 不同用户的可见范围不同 |
| 问题常常需要通读全文 | 问题通常只涉及几段 |

可见范围不同时，即使资料不多也要先按权限筛选，不能把整个库塞给模型。直接放全文时，引用照样要做：让模型引用章节号，用代码核对章节存在。

**出错时按顺序排查**

一个答错的问题，从链路上游往下查，找到第一个出问题的环节：

1. 资料里本来有没有答案。没有，就该弃答（Day17）。
2. 解析后的文本里有没有这段话。
3. 这段话是否完整地落在某个切片里。
4. 这个切片是否出现在检索候选里（召回）。
5. 重排之后它是否还在送进模型的那几条里。
6. 它在上下文里，模型是否用对了。
7. 引用是否指向了它。

前五步只看检索，不需要调用生成模型就能检查。实践中很多“模型答错了”，查下来是前几环的问题，所以检索和生成要分开评（Day28）。

### 阅读材料

- [Introducing Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval) 开头关于“直接用更长的提示词”的说明。

### 动手练习

1. 为主线项目画出入库和查询两条链路，每一环写一句：用什么实现、产出什么、出错时在哪里能看到。
2. 列出主线项目准备收录的资料（套餐说明、退订规则、课程手册、产品说明等），估算总 token 数，并按上面的对照表判断：哪些资料可以直接放进上下文，哪些必须走检索，理由是什么。
3. 想一个你见过的答错的问题，按“出错时按顺序排查”的七步写下你会在每一步看什么。

### 自检

1. 资料总量很小，但不同用户可见范围不同，为什么仍然不能把全部资料直接放进上下文？
2. 排查一个答错的问题时，为什么先查检索、后查生成？
