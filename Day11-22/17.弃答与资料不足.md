## Day17 - 弃答与资料不足

> 知识检索 ｜ 建议用时 1 小时

> **一句话**：资料里找不到依据时，系统应当明确说“这个我答不了”，并说清缺的是什么。
>
> **放在全局看**：弃答是带引用回答（Day16）的另一半结果，和“回答”同等重要。评估集里“应当弃答”这一类用例（Day25）专门检查它。

### 学习目标

- 能列出系统应当弃答的几种情况，以及每种在链路的哪一步判定。
- 会把弃答设计成带显式标记的结果，让下游代码不必去解析文字。
- 知道怎样在有依据率和弃答率之间取得平衡。

### 核心概念

**打个比方**：像一位靠谱的客服：手册上查不到的事，他会说“手册里只写了国内使用的规定，跨境使用我这里查不到，建议您联系某某渠道”，而不会凭印象给你一个答案。

**什么时候应当不回答**

| 情况 | 例子 | 在哪一步判定 |
| --- | --- | --- |
| 检索没有取回候选 | 问一个资料从未涉及的话题 | 检索之后，代码直接判定，不调用生成模型 |
| 候选都不相关 | 取回的都是别的套餐的切片，重排分数都低于阈值 | 重排之后，代码按阈值判定 |
| 证据相关但不够 | 资料只写了标准套餐的退订期限，问的是高级套餐 | 生成时，由模型在结构化输出里给出 |
| 引用校验后没有剩下结论 | 所有结论的引用都非法（Day16） | 校验之后，代码判定 |

能由代码判定的，尽早判定，省掉一次模型调用，也少一次编造的机会。阈值不要凭感觉定，用评估集里应当回答和应当弃答的两类用例去调。

**弃答是一等结果**

不要靠在回答里找“抱歉”“无法回答”这类字样来判断是否弃答。模型的措辞会变，下游代码、评估和界面都需要一个确定的字段：

```python
from dataclasses import dataclass, field
from typing import Literal

@dataclass
class AnswerResult:
    status: Literal["answered", "partial", "abstained"]
    claims: list = field(default_factory=list)        # Day16 校验后保留的结论
    reason: Literal["no_candidates", "low_relevance",
                    "insufficient_evidence", "citations_invalid", None] = None
    missing: list[str] = field(default_factory=list)  # 缺了哪些信息，用于向用户说明
```

模型那一侧，在 Day16 的回答 schema 里加一个 `insufficient` 布尔字段和 `missing` 列表，让它在证据不够时如实填写。`partial` 用于问题的一部分有依据、另一部分没有的情况：有依据的部分照常带引用回答，没有依据的部分明确列出。

**怎样对用户说**

- 说清找到了什么、缺了什么：“资料中有标准套餐的退订规则，没有找到跨境使用的说明。”
- 给出下一步：应该去查哪类资料，或者找谁确认。
- 不猜测，也不给“一般来说”的常识性答案，那正是用户无法核对的内容。
- 不提及提问人无权查看的文档。对他来说，这些内容就是“没有找到”。说出“有一份相关文档你没有权限”，本身就泄露了文档的存在（Day21）。

**两种失败要一起看**

| 失败 | 表现 | 只盯一个指标的后果 |
| --- | --- | --- |
| 该答不答 | 资料里有，系统却弃答 | 只追求“不出错”，系统会什么都不敢答 |
| 不该答却答 | 资料里没有，系统编了一个答案 | 只追求“答得多”，系统会越来越敢编 |

所以至少同时看三个数，并按用例类别分别统计：

- 在“应当回答”的用例上：回答率，以及回答中结论有依据的比例（有依据率，由 Day27 的评审员判）。
- 在“应当弃答”的用例上：正确弃答的比例。

调阈值、改提示词之后，三个数一起比。弃答率在线上突然升高，常常是入库出了问题，例如一批文档解析失败（Day12），值得做成告警（Day31）。

**进评估集**

[评估集格式示例](../模板/评估集格式示例.md) 里的 `should-abstain` 类别和 `mustAbstain` 字段，就是用来检查这里的 `status` 的，可以完全由代码评分（Day26）。每类弃答原因都至少放几条用例，也要放几条“看起来像该弃答、其实资料里有”的用例，防止系统过度弃答。

### 动手练习

1. 为主线项目定义 `AnswerResult`，并把 Day16 的回答 schema 扩展出 `insufficient` 和 `missing` 字段。
2. 写五个问题：上表前三种情况各至少一个，外加一个“部分有依据”的问题；第四种情况用替身模型返回非法引用来模拟。为每个问题写出你期望系统对用户说的话。
3. 用这批问题加上五个应当回答的问题，分别统计回答率、有依据的比例和正确弃答率，记下当前的重排分数阈值。
