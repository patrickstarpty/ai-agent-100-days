## Day19 - 图谱增强检索与关系问答

> 知识检索 ｜ 建议用时 1 小时

> **一句话**：先照常取回切片，从切片找到其中的实体，再沿图走一两步取出相关的关系，回答时同时引用关系边和原文。
>
> **放在全局看**：这是 Day18 建好的图在查询时的用法。它叠加在混合检索（Day14）和重排（Day15）之上，引用规则沿用 Day16，权限规则沿用 Day21。

### 学习目标

- 能说清从切片到实体、到邻居、到路径的扩展过程，并给每一步定上限。
- 会让回答同时引用关系边和原文切片，并做校验。
- 知道图未就绪或中途变化时怎样退化，且不说假话。

### 核心概念

**打个比方**：像在地铁图上查路线：先找到你所在的站（种子实体），只看相邻的一两站和几条换乘路线（有限扩展），不必把整张线网都背下来。一次查询从头到尾只看同一版线路图，不会前半程看旧版、后半程看新版。

**从切片到实体，再到邻居**

关系问题，例如“退款规则乙适用于哪些套餐”“进阶课程之前要先学完什么”，答案往往散在多篇文档里，单靠切片检索很难一次取全。图谱增强检索分四步：

1. **照常检索。** 混合检索加重排，取回切片。这一步已经按权限过滤。
2. **选种子实体。** 查出这些切片里提到的实体（入库时记下的“切片 → 实体”对应表），按确定的规则打分，取前几个作为种子。
3. **扩展邻居。** 从种子出发，沿边走一到两跳，取出邻居和边。
4. **找短路径。** 在扩展出的子图里，找种子两两之间长度不超过 2 的最短路径，用来回答“A 和 B 有什么关系”。

每一步都有明确的上限，并且有测试（Day43、Day45）：

```python
from collections import Counter, deque

MAX_SEEDS, MAX_HOPS, MAX_PER_NODE, MAX_EDGES = 5, 2, 10, 30

def pick_seeds(ranked_chunks: list[str], mentions: dict[str, list[str]]) -> list[str]:
    """名次越靠前的切片里提到的实体，分数越高。平局按实体 ID 排，结果可复现。"""
    score = Counter()
    for rank, chunk_id in enumerate(ranked_chunks, start=1):
        for entity in mentions.get(chunk_id, []):
            score[entity] += 1 / rank
    return [e for e, _ in sorted(score.items(), key=lambda x: (-x[1], x[0]))[:MAX_SEEDS]]

def expand(graph, seeds: list[str], can_see) -> list:
    """广度优先扩展。graph.edges_of(node) 按 edge.id 排序返回；can_see 以提问人身份判断。"""
    taken, edges = set(), []
    seen, queue = set(seeds), deque((s, 0) for s in seeds)
    while queue and len(edges) < MAX_EDGES:
        node, depth = queue.popleft()
        if depth >= MAX_HOPS:
            continue
        visible = [e for e in graph.edges_of(node) if can_see(e)]   # 先过滤权限，再截断
        for edge in visible[:MAX_PER_NODE]:
            if edge.id in taken:
                continue
            taken.add(edge.id)
            edges.append(edge)
            nxt = edge.other(node)
            if nxt not in seen:
                seen.add(nxt)
                queue.append((nxt, depth + 1))
            if len(edges) >= MAX_EDGES:
                break
    return edges
```

`can_see(edge)` 的判断依据是这条边的证据切片：提问人看不到证据，就看不到这条边（Day18）。

**确定性启发式**

种子怎么选、邻居按什么顺序取、超出上限时丢哪些，全部由代码里的固定规则决定，模型不参与“往哪里走”。这样同样的问题、同一版图，每次得到同样的子图，可以写测试，也可以做回归评估（Day30）。这是一套简单的启发式，模型没有在图上自由探索的空间。它可能漏掉更远处的关系，所以上限和打分规则要用关系类用例来调。GraphRAG 的 local search 用的是另一种起点：用问题去匹配实体描述来选实体，再把相关的文本、关系等按优先级裁剪进一个固定大小的上下文。两者都是“有限扩展、按预算裁剪”。

**同时引用关系和原文**

关系边作为证据交给模型时，单独编号，并带上它的证据切片：

```text
<relation id="R1" evidence="E3">退款规则乙 - APPLIES_TO - 标准套餐</relation>
<evidence id="E3" source="退款规则 第 3 节">本规则适用于标准套餐及……</evidence>
```

模型的一条结论可以引用 `["R1", "E3"]`。校验在 Day16 的基础上加两条：R 标签必须属于本次扩展出的边；每条被引用的边，它的证据切片也必须在这次的证据里，用户点开时能看到原文。

**钉住同一个图版本**

请求开始时读一次当前图版本号，本次请求的所有图查询都只读这个版本，并把版本号记进追踪。不能出现种子来自旧版、邻居来自新版的情况。

**退化为只用切片**

| 情况 | 处理 |
| --- | --- |
| 图还在构建，没有就绪的版本 | 跳过第 2~4 步，只用切片回答 |
| 请求过程中钉住的版本被清理，读取失败 | 丢弃已取到的图结果，只用切片回答 |
| 图查询超时或报错 | 同上 |

退化时，结果里带上 `graph_used: false` 和原因。只用切片答不全一个关系问题时，要说“关系信息暂时不可用，以下仅依据原文”，不能说“资料里没有这层关系”，那是一句假话。

**权限照样适用**

图里的每条边、合并后的每个实体，都是原始资料的派生物（Day21）。过滤在扩展时就做，不要先扩展完再删，否则上限会被看不见的边占满，可见的关系反而取不到。

### 动手练习

1. 在 Day18 建的图上实现 `pick_seeds` 和 `expand`，为每个上限写一个测试：构造一个超过上限的图，确认结果不超过上限，且两次运行结果相同。
2. 写三个关系问题，例如“退款规则乙适用于哪些套餐”“高级套餐 2.0 取代了哪个套餐”“进阶课程之前要先学完什么”，比较只用切片和加上图谱时的回答与引用。
3. 模拟图未就绪：让图版本读取返回空，确认系统退化为只用切片，结果里标明了原因，回答里没有“资料里没有”这类说法。
