## Day12 - 文档解析与切片

> 知识检索 ｜ 建议用时 1 小时

> **一句话**：把各种格式的文件变成带位置的文本，再切成大小合适、有稳定编号、能找回原文的小段。
>
> **放在全局看**：这是 Day11 那张链路图上入库的第一步，后面的检索（Day13~15）、引用（Day16）和权限（Day21）都建立在它的产物上。切片丢了的内容，任何检索手段都找不回来。

### 学习目标

- 知道常见格式各自的解析难点，并能让解析失败被明确报告出来。
- 能比较三种切片策略，为自己的资料选一种。
- 会设计切片的稳定 ID、内容摘要和回到原文的锚点。

### 核心概念

**打个比方**：像把一本厚手册拆成卡片放进卡片柜：每张卡片写一个完整的意思，背面记下出自第几页第几节，卡片编号不因重新整理而乱掉，原书也留在架上备查。

**解析：先变成带位置的文本**

| 格式 | 难点 | 要保留的位置信息 |
| --- | --- | --- |
| 有文字层的 PDF | 多栏排版、页眉页脚混进正文、表格被拆成散乱的词 | 页码 |
| 扫描件和图片 | 没有文字层，必须 OCR，识别会出错 | 页码，以及“这是 OCR 结果”的标记 |
| DOCX | 标题样式决定结构；修订和批注要决定收不收 | 标题层级（节路径） |
| Markdown、HTML | 结构清楚，标题天然就是边界 | 节路径 |
| 表格、电子表格 | 一行脱离表头就读不懂 | 工作表名、行号 |

解析最危险的失败是静默的：一个扫描版的退订规则 PDF 解析出空文本，入库流程照常完成，检索时这份文档就像不存在，问到它时系统会弃答甚至答错，没人知道原因。所以每次入库都要产出一份报告，每份文件一行状态：

```python
from dataclasses import dataclass
from typing import Literal

@dataclass
class ParseResult:
    doc_id: str
    status: Literal["ok", "partial", "needs_ocr", "failed"]
    pages: int
    chars: int
    note: str = ""   # 例如“第 3~5 页无文字层，已用 OCR”或“未配置 OCR，已跳过”
```

文件不为空、解析出的文字却极少，就判为 `needs_ocr` 或 `partial`，进报告，不进索引。用了 OCR 的切片带上标记，方便日后排查识别错误。

**三种切片策略**

| 策略 | 做法 | 适合 | 风险 |
| --- | --- | --- | --- |
| 固定长度 | 按字数或 token 数切，相邻切片重叠一小段 | 结构混乱的长文本 | 一条规则被拦腰切断 |
| 按文档结构 | 按标题、段落、表格行切，过长的节再细分 | 手册、规则、产品说明 | 节的长短差别大 |
| 父子切片 | 用小切片做检索，命中后把它所在的整节交给模型 | 问题要靠小段命中、回答要看完整上下文 | 父节过大时占用上下文 |

有清晰标题的资料优先按结构切。表格按行切时，每个切片都带上表头，例如“套餐名称｜月费｜退订期限”这一行要和它的表头一起入库。切片丢失的背景，可以按 Day15 的做法补一段说明。

**稳定的 ID 和内容摘要**

文档更新后，大部分切片没变。要做增量更新，就得知道哪些切片是同一个，哪些内容变了：

```python
import hashlib

def chunk_id(doc_id: str, section_path: str, n: int) -> str:
    """同一节里的第 n 段。只要节的标题不变，ID 就不变。"""
    return f"{doc_id}#{section_path}#{n}"

def content_hash(text: str) -> str:
    normalized = " ".join(text.split())        # 忽略空白差异
    return hashlib.sha256(normalized.encode("utf-8")).hexdigest()
```

ID 管“它是谁”，摘要管“它变没变”。重新入库时，ID 相同、摘要相同的跳过；摘要变了的重新算向量；旧 ID 消失的删除。ID 不要直接用内容摘要，否则改一个字，ID 就变，已有的引用和评估集里的期望会全部失效。也不要只用全文里的序号，否则在开头插一段，后面所有切片都会错位。用节路径加节内序号，变动只影响一节。

**回到原文的锚点**

每个切片记下它在原文中的位置：页码、节路径，必要时加字符偏移。Day16 的引用点开后要跳到这里，审核的人才能核对。

**保留原件**

原始文件连同版本号和摘要一起保存，解析出的文本只是派生物。解析器升级、切片策略调整时，可以从原件重新生成；用户点开引用时，看到的也应当是原件。原件和切片都要带上源系统的权限信息（Day21）。

### 动手练习

本课和后面几课的练习可以直接用 `samples/corpus/` 里的虚构语料（套餐说明新旧两版、退订规则、课程手册、价目表 CSV、产品说明、FAQ 等），不必自备材料；`manifest.json` 记录了每份文件的格式、版本、可见组和是否需要 OCR。

**20 分钟必做**

1. 为 `samples/corpus/` 里的每份文件（或你自己挑的五份不同格式的文件，建议包含一份扫描件和一份价目表）写出解析方式和要保留的锚点。
2. 实现 `ParseResult` 报告：用 `manifest.json` 里标为需要 OCR 的那份文件，或自己放一份没有文字层的 PDF，确认它以 `needs_ocr` 出现在报告里，并且没有进入索引。

**课后选做**

3. 把一份课程手册按结构切片，修改其中一节的一句话后重新入库，打印出“新增、变更、删除、未变”四类切片的数量，确认只有那一节变化。
