## Day13 - 向量检索

> 知识检索 ｜ 建议用时 1 小时

> **一句话**：把文字变成一串数字（向量），意思相近的文字向量也相近，检索就是找离问题最近的那些切片。
>
> **放在全局看**：向量检索负责“意思对得上”的召回，是混合检索（Day14）的一半，后面还有重排（Day15）。它对精确的编号和名称不敏感，这正是需要关键词检索的原因。

### 学习目标

- 能用自己的话说清 embedding、相似度和近似最近邻。
- 知道向量索引和 embedding 模型绑定在一起，换模型必须重建。
- 能举出向量检索答不好的问题类型。

### 核心概念

**打个比方**：像图书馆按主题摆书：讲退订的书都放在同一排，你说“我想退掉套餐”，管理员直接带你到那一排，哪怕你没说出“退订”这个词。可你要找的如果是一本特定编号的书，按主题摆放就帮不上忙。

**embedding 是什么**

embedding 模型把一段文字变成一个固定长度的数字列表。训练让意思相近的文字落在空间里相近的位置：“怎么取消套餐”和“退订流程说明”用词不同，向量却很接近。入库时为每个切片算一次向量存起来；查询时为问题算一次向量，再找最近的切片。

**相似度**

最常用的是余弦相似度，看两个向量的方向有多接近：

```python
import math

def cosine(a: list[float], b: list[float]) -> float:
    dot = sum(x * y for x, y in zip(a, b))
    return dot / (math.sqrt(sum(x * x for x in a)) * math.sqrt(sum(y * y for y in b)))

def search(query_vec, chunks, top_k=20):
    """精确检索：和每个切片都比一次。只适合小数据量和做对照。"""
    scored = [(cosine(query_vec, c["vec"]), c["chunk_id"]) for c in chunks]
    return sorted(scored, reverse=True)[:top_k]
```

相似度只能用来排序，分数本身没有统一的含义。同一个模型下 0.8 算不算相关，要用自己的评估集看；换了模型，分数的分布也会变。

**近似最近邻**

上面的写法要和每个切片比一次，切片到了几十万、几百万，查询就太慢。近似最近邻（ANN）事先为向量建一个索引结构，查询时只比较一小部分候选，换来速度，代价是偶尔漏掉真正最近的几个。常见的 HNSW 把向量连成多层的“邻居图”，查询从最稀疏的上层出发，每一步走向离问题更近的邻居，逐层下降到最密的底层。索引参数控制“查多少候选”，也就控制了速度和召回之间的取舍。调参时，在一批问题上把 ANN 的结果和精确检索对比，看漏了多少。

**索引和模型绑在一起**

- 向量的维度由模型决定，索引建好后维度就固定了。
- 不同模型算出的向量互相不可比，即使维度碰巧相同也一样。查询和切片必须用同一个模型。
- 换 embedding 模型，就要把全部切片重新算一遍，建一个新索引。稳妥的做法是新旧索引并存，用评估集（Day25）对比通过后再切换。
- 索引的元数据里记下模型名称和版本，查询代码启动时核对，对不上就拒绝服务。

**多语言**

多语言 embedding 模型可以把中文问题和英文文档映射到同一个空间，适合混合语言的资料。效果在不同语言上并不均匀，评估集里要按语言分别统计（模板里的 `locale` 字段就是为此准备的）。另外，问题通常短，切片通常长，有的模型要求查询和文档使用不同的前缀或指令，按所用模型的说明来做。

**向量检索不擅长什么**

| 问题类型 | 例子 | 原因 |
| --- | --- | --- |
| 精确编码和 ID | “套餐 PLN-0420 的月费” | 编号本身没有语义，PLN-0420 和 PLN-0421 在向量上可能很难区分 |
| 罕见名称 | 一个刚上市产品的代号 | 模型没见过这个词，表示不准 |
| 数字和否定 | “退订期限 15 天”和“30 天”；“可以退订”和“不可退订” | 两句话整体很接近，关键差别只在一个数字或一个否定词 |
| 版本区分 | 新版和旧版退订规则 | 内容高度相似，向量难以分开 |

这些问题交给关键词检索（Day14），或者用元数据过滤，例如只查当前生效版本。权限条件同样作为过滤条件进入向量查询（Day21）。

### 动手练习

1. 用你能用到的任意 embedding 模型，为主线项目的十个切片算向量，再用十个问题做精确检索，记录每个问题的正确切片排在第几。
2. 专门写三个含套餐编号或产品型号的问题，观察向量检索的排名，记下来留给 Day14 对比。
3. 为主线项目写一份“换 embedding 模型”的操作步骤：新索引怎么建、怎么对比、怎么切换、旧索引何时删除。

### 自检

1. 两个 embedding 模型输出的维度相同，为什么仍然不能混用同一个索引？
2. 近似最近邻牺牲了什么，你会怎样度量这部分损失？
