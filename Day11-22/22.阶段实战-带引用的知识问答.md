## Day22 - 阶段实战：带引用的知识问答

> 知识检索 ｜ 建议用时 1 小时

> **一句话**：把本阶段的零件装成一条完整链路：导入十份文档，混合检索，回答带经过校验的引用，没有依据时弃答，再用十道题验收。
>
> **放在全局看**：这条链路就是主线项目的知识问答内核。评估阶段（Day23~34）会在它上面建正式的评估，编排阶段（Day35~46）会把它变成图里的一个子图。

### 学习目标

- 把 Day11~21 的内容组合成一个可运行的命令行知识问答程序。
- 用一份十道题的小评估集和一份验收清单检查自己的实现。

### 核心概念

**需求**

| 功能 | 要求 | 对应课程 |
| --- | --- | --- |
| 语料 | 约十份文档：套餐说明、套餐价目表、退订规则（新旧两版）、课程手册、产品说明、常见问题，至少一份 PDF、一份表格、一份扫描件 | Day12 |
| 解析 | 每次入库输出报告；扫描件明确标为需要 OCR 或已 OCR，不能静默跳过 | Day12 |
| 切片 | 按结构切片；每个切片有稳定 ID、内容摘要、锚点、文档版本、可见用户组 | Day12、Day21 |
| 索引 | 关键词索引加向量索引；索引元数据记录 embedding 模型 | Day13、Day14 |
| 检索 | 两路检索都带权限和版本过滤，用 RRF 融合 | Day14、Day21 |
| 回答 | 证据编号，结构化输出结论和标签，代码校验引用 | Day16 |
| 弃答 | `AnswerResult` 带显式状态和原因，向用户说明缺什么 | Day17 |
| 评估 | 十道题，其中两道应当弃答，脚本自动评分 | Day25 |

权限只需最简单的一版：给一份文档（例如客服操作手册）设为只有 `staff` 组可见，命令行用 `--user` 指定提问人和他所属的组。

评估集沿用 [评估集格式示例](../模板/评估集格式示例.md) 的字段。十道题的建议构成：

| 类别 | 题数 | 覆盖点 |
| --- | --- | --- |
| 应当回答 | 8 | 含套餐编号的题、口语化提问的题、答案在价目表里的题、答案在扫描件里的题（OCR 后）、需要两份文档合起来回答的题、新旧版规则不同的题 |
| 应当弃答 | 2 | 一题资料完全没有涉及；一题资料里只有相近对象的信息，例如问高级套餐、资料只写了标准套餐 |

**三个容易做错的地方**

评估只看最终回答。一道题失败了，要能看出是没取回、取回了却被截掉，还是模型没用对。`run_eval.py` 对每道题额外记录：期望的来源文档是否出现在候选里，排第几。这就是 Day28 检索评估的雏形。

语料变了，分数却没人发现原因。`golden.json` 里写上 `corpusDigest`，评估脚本运行前核对当前语料的摘要，对不上就提醒复核期望。

旧版规则混进回答。新旧两版退订规则内容很像，向量检索很难分开。版本要作为过滤条件进入查询，不能指望模型从内容里分辨哪个是新的。

### 动手练习

按上面的布局实现。先写 `golden.json`，把每道题的期望写成可由代码检查的条件，再写代码，最后逐条验收。

**验收清单**

入库

- [ ] 入库报告列出全部文件；扫描件的状态是 `needs_ocr`，或已 OCR 并在切片上带有标记。
- [ ] 每个切片都有 `chunk_id`、`content_hash`、锚点（页或节）、文档 ID、文档版本和可见组。
- [ ] 修改课程手册中的一节后重新入库，只有这一节的切片被重新计算向量，其余跳过。
- [ ] 价目表的每个切片都带着表头。
- [ ] 索引元数据里有 embedding 模型名称；用另一个模型名启动查询时，程序拒绝服务并说明原因。

检索

- [ ] 含套餐编号的问题，正确切片在 RRF 融合后的前五名里。
- [ ] “不想用了怎么取消”这类口语化问题，能取回退订规则的切片。
- [ ] 以不属于 `staff` 组的用户提问客服操作手册的内容，两路候选里都没有这份文档的切片。
- [ ] 问退订期限时，候选里只有当前生效版本的退订规则。
- [ ] 同一个问题连续运行两次，`hybrid` 返回的顺序完全相同。

引用

- [ ] 每条展示出来的结论都至少有一个合法引用，命令行显示文档名和锚点。
- [ ] 用替身模型返回一个引用 `E9` 的结论，这条结论被丢弃，丢弃数量写进日志。
- [ ] 结论里的数字都能在被引用的切片原文里找到；故意改错一个数字时，检查能发现。

弃答

- [ ] 两道应当弃答的题，`status` 是 `abstained`，`reason` 有值，对用户的说明讲清了缺什么。
- [ ] 检索没有候选时，没有调用生成模型（日志可证）。
- [ ] 无权用户问到受限内容时，回答里不提及那份文档的存在。

评估

- [ ] `golden.json` 有十道题，其中两道 `should-abstain`，带 `corpusDigest` 和真实的标注人。
- [ ] `run_eval.py` 输出每道题的通过与否和失败原因，以及三个汇总数：应当回答题的通过数、应当弃答题的通过数、期望来源出现在候选里的题数。
- [ ] 记录一次基线结果，写明当时用的模型、embedding 模型和弃答阈值。

**进阶**

- 加上重排（Day15），比较加之前和加之后的三个汇总数。
- 为切片加上下文说明（Day15），重点看新旧版规则那道题是否改善。
- 用 Day18、Day19 的方法为套餐和规则建一张小图，增加两道关系题，回答同时引用关系边和原文。
- 增加两道 `must-not-appear` 权限用例（Day21），并纳入自动评分。
- 加一个只判“结论能否从被引用切片推出”的 LLM 评审员，先用十几条人工标注校准（Day27）。
