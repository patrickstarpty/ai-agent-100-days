## Day66 - 阶段复盘：信任模型与威胁模型

> 安全与治理 ｜ 建议用时 1 小时

> **一句话**：把“信任谁、防什么、还剩什么风险”写成文档。
>
> **放在全局看**：这是第三份阶段文档。它把 Day54 的信任等级、Day55 的 agent 定义和 Day59 的身份设计收成信任模型，把 Day57 的威胁模型草图和 Day61 的对照结果定稿；评审清单在这里加上“工具与安全”一节，Day97 会把整份清单收尾。

### 学习目标

把本阶段的结论收成两份文档，并复核 Day61 用公开风险清单做的对照结果。

### 产出一：工具与 Skill 的信任模型

用 [决策记录模板](../模板/决策记录模板.md) 写一份决策记录，回答：

- 内容按可信程度分几级？可以从 Day54 的四级出发：平台自带、已审核、个人导入、外部来源（外部 MCP server 提供的工具描述也算这一级）。
- 每一级的内容能做什么：能否进入系统提示词、能否触发写操作、能否访问网络。
- 导入的 Skill 是否执行其中的代码？如果不执行，怎样保证。
- 写操作由谁的身份执行，agent 自己是否持有写权限。

### 产出二：威胁模型定稿

在 Day57 的草图上补全：每条“三要素同时出现”的路径，采取了什么控制，剩余风险是什么，谁接受了这个剩余风险。

### 复核 Day61 的对照结果

Day61 已经用 [OWASP Top 10 for Agentic Applications for 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026) 为一个 agent 逐条写了结论。这里不重做一遍，只复核：

- 上次的每条待办是否关闭。关闭的，补上证据（代码、配置、测试或审批记录的位置）；没关闭的，写明原因和新的期限。
- 本阶段后几课（Day62~65）加上的控制，有没有让某条“尚无控制”变成“已有控制”，证据是否指向一条会失败的测试。
- 系统自 Day61 以来新增的 agent、工具或数据源，是否需要补做对照。

### 评审清单的“工具与安全”一节

打开 [设计评审清单](../模板/设计评审清单.md) 的“工具与安全”一节，对照模板，按你的项目增删并写明理由。模板里这一节的问题是：

- 这个 agent 占了致命三要素里的几项？去掉了哪一项？
- 外部内容（工单、网页、导入的 Skill、MCP 工具描述）能否影响系统提示词或触发写操作？
- 运行身份和权限范围是否明确？是否随任务收窄？
- 工具有没有注册表和风险分级？
- 最终放行靠的是模型判断，还是确定性规则？

### 阶段验收

- [ ] Day61 的对照结果已复核：每条待办或已关闭并附上证据，或写明了未关闭的原因和新期限。
- [ ] 评审清单的“工具与安全”一节已按项目增删，每处增删都写了理由。
- [ ] 在测试环境里导入过一个真实的外部 Skill，并确认其中的代码没有被执行。
- [ ] 威胁模型里每条剩余风险都有明确的接受人。
