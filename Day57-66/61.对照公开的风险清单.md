## Day61 - 对照公开的风险清单

> 安全与治理 ｜ 建议用时 1 小时

> **一句话**：拿一份公开的风险清单逐条对照自己的设计，每条给出结论和证据，还没有控制的变成有人负责的待办。
>
> **放在全局看**：Day57 是从自己的系统出发找风险，容易只看到自己想到的；公开清单从外部补上盲点。对照的结果写进 [威胁模型模板](../模板/威胁模型模板.md) 第五节，在 Day66 定稿。

### 学习目标

- 掌握“三选一结论 + 证据 + 待办”的对照方法。
- 能区分什么算控制的证据，什么不算。
- 用 OWASP 的 agent 应用风险清单为自己的一个 agent 做一次完整对照。

### 核心概念

**打个比方**：像出远门前对着一张通用的行前清单收拾行李：清单是别人总结的，每个人的行程不同。有的项用不上，写明为什么；有的已经装好，能指出在哪个包里；还没装的，记下谁在出发前去买。

**对照的四步**

1. **定清单和版本。** 记下清单的名称和版本，清单更新后要重新对照。
2. **定范围。** 一次只对照一个 agent 或一条流程，结论才具体。
3. **逐条判定。** 每条三选一：不适用、已有控制、尚无控制，并附上证据。
4. **转成待办。** 每条尚无控制的结论变成一个待办，写明负责人和期限。

不设“部分控制”这个选项。只做了一部分的，按尚无控制处理，在证据里写清已有的部分，避免模糊的结论让问题消失。

**什么算证据**

| 结论 | 需要的证据 | 不算证据的 |
| --- | --- | --- |
| 不适用 | 系统里不存在这条风险的前提，并写明“出现这个前提时重新评估” | “我们的用户都是内部员工” |
| 已有控制 | 指向具体的代码、配置、测试、评估用例或审批记录 | “提示词里要求模型不要这样做”（Day57） |
| 尚无控制 | 写清缺什么、影响哪条路径 | 只写“需要加强” |

“已有控制”最好能指向一条会失败的测试：控制被去掉时，这条测试会变红。

**OWASP 的 agent 应用风险清单**

OWASP GenAI Security Project 在 2025 年 12 月发布了《OWASP Top 10 for Agentic Applications for 2026》。十项的编号和名称如下（名称照原文，后面一列是本课程的简要理解和对应的课，细节以原文为准）：

| 编号 | 名称 | 简要理解 | 相关的课 |
| --- | --- | --- | --- |
| ASI01 | Agent Goal Hijack | 外来内容改变了 agent 的目标或决策 | Day57、Day58 |
| ASI02 | Tool Misuse and Exploitation | 在已有权限内把正当的工具用在不该用的地方 | Day47、Day48 |
| ASI03 | Identity and Privilege Abuse | 借委托链、继承的凭据越权 | Day52、Day59 |
| ASI04 | Agentic Supply Chain Vulnerabilities | 第三方的工具、模型、Skill、MCP server 被篡改或本身有恶意 | Day50、Day54 |
| ASI05 | Unexpected Code Execution (RCE) | 生成或注入的代码在宿主上被执行 | Day60 |
| ASI06 | Memory & Context Poisoning | 被存下来的记忆、摘要、检索库被污染，影响以后的推理 | Day43、Day58 |
| ASI07 | Insecure Inter-Agent Communication | agent 之间的消息缺少认证、完整性或校验 | Day80 |
| ASI08 | Cascading Failures | 一处错误沿着 agent、工具和流程放大扩散 | Day45、Day78 |
| ASI09 | Human-Agent Trust Exploitation | 人过度信任 agent 的建议，在没有独立核对的情况下批准 | Day41、Day65 |
| ASI10 | Rogue Agents | agent 偏离了预期的职能或授权范围 | Day59、Day62 |

原文每一项都有描述、常见情形、攻击场景和缓解建议，还说明了相邻条目之间怎样划界（例如 ASI01 是直接改变目标，ASI06 是污染存下来的上下文）。判定时先读原文的这几部分，再对照自己的系统。

**结论怎样进入待办**

每条结论记成一条结构化记录，和威胁模型放在一起，进入版本管理：

```yaml
- item: ASI03
  scope: 案例 B / 编码 agent
  verdict: 尚无控制
  evidence: 编码 agent 和需求澄清 agent 共用一个服务账号，能推送到任何分支
  todo: 为每个 agent 建立独立身份；推送只允许到 agent 自己的分支
  owner: <负责人>
  due: <期限>
```

待办进入团队平时用的待办系统，和其他工作一起排期。下次对照时，先检查上次的待办是否关闭，关闭的要补上证据。

**清单的边界**

公开清单只覆盖常见风险。Day57 从自己系统里找出的路径，即使清单里没有对应项，也要保留。

### 动手练习

1. 下载上面的文档，选主线项目里的一个 agent，按十项逐条写结论和证据。
2. 至少写出两条“尚无控制”的待办，带负责人和期限。
3. 回到 [威胁模型模板](../模板/威胁模型模板.md)，把结果填进第五节。

### 自检

1. “提示词里已经要求模型不要越权”为什么不能作为“已有控制”的证据？
2. 一项风险被判为“不适用”，什么情况下需要重新评估？
