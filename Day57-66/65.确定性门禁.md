## Day65 - 确定性门禁

> 安全与治理 ｜ 建议用时 1 小时

> **一句话**：agent 负责建议、生成和诊断，它的产出要成为正式内容，必须通过一道由规则或人把守的门。
>
> **放在全局看**：这是整门课反复出现的立场“模型提议，代码或人裁决”的落地形式。它把 Day04 的结构校验、Day26 的代码评分器、Day30 的 CI 和 Day41 的人工确认串成一条发布路径，Day82 的提议与采纳、Day92 的研发流程门禁都按这个形状来设计。

### 学习目标

- 把 agent 的产出设计成“草稿 → 校验 → 批准 → 发布”的状态流转，不需要人批准的类别校验后直接发布。
- 为一类产出选出合适的门禁组合。
- 把门禁当作代码来测试，并证明它确实能拦住。

### 核心概念

**打个比方**：像出版社出书：作者和编辑可以反复改稿，书要付印，得先过校对的检查表，再由总编签字；印厂只认签过字的那一版。

**从草稿到权威内容**

agent 产出的一切都从草稿或提议开始：一段回答、一份测试方案、一次代码改动、一条工单评论。它要成为权威内容（别人会依赖的那一份），必须经过确定性校验和一个显式的发布步骤。

```python
GATE = {("draft", "validated"): "gate"}            # 只有门禁代码能推进

WITH_APPROVAL = {**GATE,                            # 需要人批准的类别
    ("validated", "approved"): "human",
    ("approved", "published"): "publish",           # 以批准人的身份写入（Day59）
}
NO_APPROVAL = {**GATE,                              # 不需要人批准的类别
    ("validated", "published"): "publish",          # 以发起人的身份写入，过了门禁直接发布
}

def advance(item: dict, to: str, actor_kind: str) -> dict:
    table = WITH_APPROVAL if item["needs_approval"] else NO_APPROVAL
    need = table.get((item["status"], to))
    if need != actor_kind:
        raise PermissionError(f"{actor_kind} 不能把 {item['status']} 推进到 {to}")
    return {**item, "status": to}
```

一类产出要不要人批准（`needs_approval`）由规则按类别事先定好，不由 agent 填写。agent 的身份只能写草稿区，权威存储只接受发布步骤的写入。草稿在批准之后被改动，状态退回草稿，之前的批准作废。

**门禁的例子**

| 门禁 | 拦什么 | 规则由谁定 |
| --- | --- | --- |
| 结构校验 | 字段缺失、类型不对、枚举越界（Day04） | 下游的使用方 |
| 引用校验 | 引用指向不存在的片段（Day16） | 知识库负责人 |
| 测试与构建 | 代码改动破坏已有功能（Day30） | 代码的负责人 |
| 策略检查 | 改了不允许 agent 改的路径、引入未经审核的依赖、改动范围超限、修改了权限配置 | 安全负责人 |
| 人工审批 | 需要判断和担责的决定（Day41） | 业务负责人 |

以案例 B 为例，代码托管平台的分支保护就是现成的门禁：撰写时（2026 年 10 月）GitHub 的受保护分支可以要求合并前通过评审和状态检查、新提交让旧批准失效（以官方文档为准），编码 agent 只推送到自己的分支，合并由这些规则放行，细节见 Day92；其他代码托管平台也有类似的分支保护设置，以平台文档为准。

**模型不做最后一道门**

LLM 评审员（Day27）可以作为门禁的输入，例如给审批人一个“可能缺少依据”的提示，但不单独作为放行条件。它的判断有波动，它读到的内容可能含有注入（Day58），而且人容易过度相信它的结论，省掉自己的核对。

**门禁是代码，需要测试**

门禁的规则放在仓库里，有版本、有评审，和业务代码一样要测试。至少要有两类测试：一条已知不合格的输入被拦住，证明门禁确实能拦；门禁自身出错时按拒绝处理，避免“检查程序崩溃就当作通过”。

```python
def gate(draft: dict, known_chunks: set[str]) -> list[str]:
    problems = []
    if not draft.get("citations"):
        problems.append("没有引用")
    problems += [f"引用不存在：{c}" for c in draft.get("citations", []) if c not in known_chunks]
    return problems

def run_gate(draft: dict, known_chunks: set[str]) -> bool:
    try:
        return not gate(draft, known_chunks)
    except Exception:
        return False                      # 门禁出错一律不放行

def test_gate_blocks_missing_citation():
    assert gate({"answer": "可以退订", "citations": []}, {"c1"}) == ["没有引用"]

def test_gate_fails_closed():
    assert run_gate(None, {"c1"}) is False   # 输入异常导致门禁报错，结果是拒绝
```
